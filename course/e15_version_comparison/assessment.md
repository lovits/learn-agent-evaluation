# 第15课样本与评测记录

## 样本是什么

[cases.jsonl](cases.jsonl) 是三个公开构造教学任务：Atlas 发布＋认证、上传认证＋容量、Shipping 当前v3。每个参考绑定全部相关源文件哈希；复用同一挂载知识库，没有把待回答问题的参考答案塞入 Agent 提示。

每题两个版本、各重复两次，共12行、6个预期配对。检索候选 k=3，唯一设计变化为 context_limit 1→3。第一步检索由实验固定、TinyRAG 真正执行，后续模型动作与回答另存；这不是自主选择第一步查询的端到端基准。

## 构造示例与真实模型分开

| 执行 | 记录 | 性质 |

| 默认 Docker | e15-suite-4d2c90f473214fbe93ada3f9390b4969 | 真实检索＋构造回答与分数，演示聚合 |

默认构造分的题族差值为 +0.5、+0.5、−1，等权平均0，重采样范围[−1,0.5]；其中运费回答故意引用旧值，不能写成真实模型退化。

真实运行配对覆盖6/6，无评分异常，单次检索协议全部满足：

| 题族 | baseline 两次 | candidate 两次 | 同题平均差值 |
|---|---|---|---|
| Atlas | 0.5、0.5 | 1、1 | +0.5 |
| Upload | 0.5、0.5 | 1、1 | +0.5 |
| Shipping | 1、1 | 1、1 | 0 |

题族等权差值1/3，近似 percentile bootstrap 范围[0,0.5]，触及0。原始回答显示，Atlas 单条资料不足，Upload 单条未覆盖认证头；增加上下文后覆盖相应事实，Shipping 两侧均识别当前规范。没有观测到原题退化，也没有足够材料证明普遍改善。

## 调用、延迟与费用

[assessment.json](assessment.json) 分别汇总两个版本的 Agent 用时和接口报告 token。每侧6次真实请求，受控首步不算模型请求；12次裁判调用、耗时和完整 usage 保存在各行 judge_calls，未混入 Agent 延迟。

总输入 token 含传输层完整提示及缓存；不能当作仅业务正文长度。reported_model 均为空，桥接报告相同默认选择方式，没有验证固定快照。美元价格与费用均为空，不能解释为零成本。小样本的调用耗时还受冷启动、缓存和服务负载影响，不作延迟优胜结论。

## 软件与发布核对

代码在 Docker 中实际执行。针对错位配对、缺评分、重复ID、题族权重和未知用量的检查通过；全仓库检查与教材图片读取一并核对。最终验证数见 assessment.json。

最初命令漏掉 Docker entrypoint 覆盖，入口仅接受 serve，因此未进入实验；失败日志保留在 runs/e15-default.log 和 e15-native.log，修正后才得到上面的两份运行记录。

上述真实实验只说明这批构造任务、当前服务和本课量表下的表现。没有人工独立标注、未固定模型快照，也不是持出基准；继续推广前应扩充题族并复核裁判。
