# e04 参考解释

[练习](exercises.md) · [教材](README.zh.md)

1. `UploadContract` 依然返回 `1.0`，因为它只负责校验 JSON 格式、三个字段是否齐全、`required_header` 与 `max_bytes` 的类型和常量值，以及 `explanation` 是否为非空字符串。至于 `explanation` 有没有答到点子上，则由 `explanation_metric` 判为 `0.0`。两项指标各司其职，不能因为结构规则通过了就认为回答内容正确。
2. 直接做字符串相等比对通常会判错。本课的 `evaluation_steps` 明确允许中英文同义表达，因此只要英文句子准确覆盖“大于 `1048576` 字节返回 `HTTP 413`”和“发送前检查文件大小”两层意思，裁判按量表应给原始 `2` 分（归一后 `1.0`）。不过模型是否真能稳定识别各类同义改写，仍需要通过更多边界用例验证。
3. 只包含一项要求且没有矛盾声明，对应 `Rubric` 中的原始 `1` 分；量表范围是 `0` 至 `2`，归一化后得到 `(1 - 0) / (2 - 0) = 0.5`；最后与 `threshold=1.0` 比较，判定为未通过（`passed=False`）。调整 `threshold` 只会改变及格门槛，不会改变 `0.5` 这个事实覆盖分。
4. 两集合交集大小为 `1`，因此 `precision = 1/2`，`recall = 1/3`，`F1 = 2/5`。把预测集清空且参考集非空时，预测项数为 `0`，`precision` 返回 `None`（未定义），`recall` 和 `F1` 为 `0.0`；把参考集清空且预测集非空时，参考项数为 `0`，`recall` 返回 `None`，`precision` 和 `F1` 为 `0.0`；两侧都为空时三项均返回 `None`。
5. `OSError` 表示调用链路本身没有跑通，无法得出回答质量好坏的结论，因此 `score` 将 `status` 记为 `"error"`、分值设为 `None` 并记录异常信息。汇总报告时除了有效样本平均分，还应同时报告总样本数、有效评分数与报错数，避免在不知情的情况下把故障样本填零或悄悄剔除。
6. 格式不合法或解释语义出错都会导致交付失败。把两个分数求平均后得到 `0.5`，既丢掉了“究竟是格式错了还是解释错了”的故障定位信息，也可能在下游设置宽松阈值时意外放行格式破损或内容空洞的样本。两项都必须达标时，应分别校验两者都处于 `status="ok"` 且各自的 `passed` 为 `True`。
