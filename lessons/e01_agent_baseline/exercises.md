# e01 练习

[教材](README.zh.md) · [参考解释](solutions.md)

## 1. 跟住一次回填

执行 `create_and_run`，在运行报告里找到一条模型动作、对应的 Bash 事件和下一条模型响应。对照 `agent_loop`，指出工具结果在哪一行加入 `messages`。

如果删掉这次回填，模型下一轮还知道命令实际输出了什么吗？

## 2. 只说完成

用一个构造响应代替模型：直接返回空 `tool_calls` 和“已完成”。把得到的运行记录交给 `evaluate`，任务规则仍用 `create_and_run`。

观察 `status`、逐项判断和 `passed`。哪些字段描述停止，哪些证据描述完成？这个构造例用于理解评分器，不计作真实模型表现。

## 3. 文件存在，但内容不对

先完成任务。保留原执行事件，将实际 `hello.py` 改为 `print("Goodbye")`，再评分。

接着只把正确文件换成单引号或增加注释。为什么这两次变化对 AST 规则的影响不同？

## 4. 报错也是任务结果

执行 `command_error`。用户要求观察原脚本的错误，不要求修复。

找到非零退出、指定错误文本和原文件哈希这三处证据。若 Agent 修好脚本再声称成功，是否仍满足这道题？

## 5. 想清楚规则的边界

只执行 `echo 'Hello, World!'`，然后停止。它能让哪几条判断通过？缺少什么？

再想一步：即使创建了正确文件，输出检查能否单独证明输出一定来自 `python3 hello.py`？如果用户更关心实际行为，下一版规则应该增加什么证据？
