## 同一个 null，三种来路

Agent 要把上传规范写成 `upload_notes.json`，其中 `max_bytes` 却是 `null`。

可能是知识库没有限额说明，也可能是文档存在但没有检索出来，还可能是模型收到资料后遗漏了它。只看最终分数，无法区分。

本课继续使用合成 v1 的1048576字节上限，保持问题和查询不变，每次只改变一个位置。

## 把改动放在链路上

| 位置 | 控制方式 | 要观察什么 |
|---|---|---|
| 资料源 | 从临时资料副本移除限额文档 | 是否本来就缺资料 |
| 检索返回 | 隐去命中、加入旧规范或噪声 | 模型实际收到什么 |
| 生成入口 | 加入错误的旧限额指令 | 证据完整时仍会怎样输出 |

这里的故障开关是有意设置的，不代表模型自然发生这些错误的比例。

原知识库保持只读。资料缺口只在临时副本里制造，避免一次练习影响后续课程。

## 只替换工具执行的位置

前面的循环已经接收 `tool_dispatch`。本课通过这个参数接入 `fault_dispatch`，其他工具继续走原实现。

检索时，先保存正常命中，再应用干预：

```python
hits = search_knowledge(QUERY, root=corpus)
before = json.loads(json.dumps(hits))
if case_id == "drop_hit":
    hits = [d for d in hits if d["id"] != "e04/limits.md"]
if case_id in ("add_old", "add_noise"):
    hits = [*hits, extra_document(case_id)]
retrievals.append({"query": QUERY, "before": before, "after": hits})
```

`before` 说明检索器原本找到了什么；`after` 才是交给模型的内容。`drop_doc` 则更早发生，在检索开始前就从资料副本移走文件。

这样，“资料没有”和“没有返回”就留下了不同证据。

## 从实际文件往回查

[`inspect_artifact`](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e07_failure_diagnosis/code.py) 重新读取文件，校验 JSON 结构，再比对认证头、上限和状态码。`null` 表示给定证据范围内未知，不表示系统没有限制。

诊断按观察值逐层判断：

```python
if artifact["status"] != "valid":
    return "artifact_error"
if not REQUIRED <= set(available_ids):
    return "knowledge_gap"
if not REQUIRED <= set(returned_ids):
    return "retrieval_gap"
if all(artifact["field_matches"].values()):
    return "no_observed_task_failure"
return "generation_mismatch_requires_review"
```

诊断函数不根据故障组名字猜答案。证据完整而产物不匹配时，它只把范围缩到生成及执行阶段，仍要继续检查指令与动作。

## 噪声指标补充了什么

DeepEval 的 Contextual Relevancy 问“返回内容有多少切题”。旧上传规范可能很切题，但已经过期。

Ragas 的 NoiseSensitivity 按事实支持关系划分上下文：能支持至少一条 reference 声明的为 relevant，其他为 irrelevant，再检查错误回答声明被哪组支持。

```text
噪声敏感度 = 被指定上下文组支持的错误回答声明数 / 全部回答声明数
```

它越低越好。如果错误是模型自己编出的，任何上下文都不支持，这个分数也可能为0。因此仍需答案正确性与阶段证据一起判断。

无关模式会排除同时被相关组支持的声明，避免两组重复计数。具体支持矩阵放在源码导读。

## 评分输入也会制造错误

参考答案若没有写明端点，裁判可能把带端点的正确声明判成不受支持。把 JSON 的 `null` 写成“系统没有配置”，又会改变原来的未知含义。

给裁判的文本投影要忠实表达原文件。修改评分输入以后，分数变化只说明评价条件变了，不能据此判断 Agent 改进。

## 先读本课的数据流

```text
资料副本 available
  → search_knowledge
  → before / 干预 / after
  → agent_loop
  → upload_notes.json
  → inspect_artifact → diagnose
```

`fault_dispatch` 只截获知识检索，查询固定为 `QUERY`。其他工具与前课保持同一路径；生成故障只改变模型入口提示，不修改检索结果。

`diagnose` 检查实际文件、可用文档和实际返回，不读取 `case.id` 来决定失败原因。一次干预只能支持当前观察，模型抽样和更多潜在因素仍需进一步控制。

## DeepEval：话题相关性的分母

[Contextual Relevancy 文档](https://deepeval.com/docs/metrics-contextual-relevancy) · [实现](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/metrics/contextual_relevancy/contextual_relevancy.py) · [RAG 指南](https://deepeval.com/guides/guides-rag-evaluation)

固定实现 `_required_params` 只要求问题和检索上下文。同步 `measure` 为每个片段生成带 statement、verdict 和 reason 的列表；异步入口可以并发处理片段。

`_calculate_score` 展平列表，数相关声明比例，空裁决默认0。它不读取 reference 来检查漏掉的必要资料，长文档拆出的更多声明还会改变权重。

## Ragas：三张支持矩阵

[Noise Sensitivity 文档](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/noise_sensitivity/) · [实现](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/metrics/collections/noise_sensitivity/metric.py) · [prompt/schema](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/metrics/collections/noise_sensitivity/util.py)

`ascore` 需要问题、回答、reference 和上下文。先拆 reference 与回答，再分别判断：

| 矩阵 | 行与列 |
|---|---|
| `retrieved2ground_truth` | 参考声明 × 上下文 |
| `retrieved2answer` | 回答声明 × 上下文 |
| `ground_truth2answer` | reference 对回答声明的支持 |

最后一项取反，得到错误回答声明。第一张表把文档分成相关和无关组，第二张表说明每组支持哪些回答声明。

## _compute_score 怎样用这些表

relevant 模式取“错误”与“被相关组任一文档支持”的交集，再对全部回答声明取均值。

irrelevant 模式同样计算，但排除也被相关组支持的声明。若三条回答中有一条只被无关组支持且为错误，无关模式就是1/3。

同一错误在两组都有支持时，只计入相关模式。错误不被任何上下文支持时，两组都可能为0；这个指标没有覆盖全部幻觉来源。

`AuditedNoise` 记录原生矩阵并调用父类聚合，允许对同组裁决切换模式。空拆解或异常矩阵可能产生 NaN 或错误，外层要分开记录。

## 先检查投影，再解释指标

`response_text` 只投影实际文件的业务字段，来源数组和最后的完成回执保留在原记录中。`null` 明确表示当前证据未知；reference 应写清任务端点与版本。

同一套字段投影用于各干预，才方便对照。阶段诊断、答案质量与噪声来源分别回答不同问题。
