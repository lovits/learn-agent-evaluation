# 第1课参考答案

## 1. 轨迹

模型给出tool_calls，循环执行Bash，记录stdout/stderr/exit_code，再把结果放回messages。
最后tool_calls为空时finished。独立验收器还要检查真实输出和文件状态，才能给出passed。

## 2. 合同变化

需求、测试输入和验收条件应属于同一版本。原标准拒绝新输出是合理的；
新标准要由新任务要求推导，不能根据希望得到的成绩倒推。hello任务约定单一print，
所以AST接受单双引号与注释，但拒绝增加额外语句。

## 3. 失败与完成

command_error要求运行原脚本并观察错误，不要求修复；exit_code非零是预期证据。
达到step_limit表示运行预算结束，不能按成功完成处理。超时、模型错误同样单独报告。

## 4. 假报成功

没有工具事件和真实结果，即使final_answer写“完成”，仍应失败。
这是对验收器的合成负例测试，不是模型真实撒谎率测量。

## 5. 局限

程序打印了预期字符串，并不自动证明任意代码质量、可维护性或任务泛化。
本课也没有用LLM裁判评价最终解释是否完整或清楚；这些问题在后续课程逐项补充。
