# e01 参考解释

[练习](exercises.md) · [循环](code.py) · [评分器](eval.py)

## 1. 工具结果进入下一轮

模型事件给出命令，Bash 事件给出实际 `result`。循环收集 `results`，通过 `messages.append({"role": "tool", "content": results})` 回填；下一次 `model(messages)` 才看得见它。

去掉回填以后，执行仍可能发生，但模型无法从消息得知真实 stdout、stderr 或退出码。最终回答就缺少这次反馈。

## 2. 停止不代表完成

空 `tool_calls` 让循环返回 `finished`。没有 Bash 事件时，`bash_was_executed` 不通过；没有输出和文件，任务规则也不通过。独立评分不会因为回答写着“已完成”而补出证据。

测试目录中的构造模型只用于检查这段逻辑。真实模型表现要从真实运行得到。

## 3. 检查现在的文件

改成 `Goodbye` 后，旧 stdout 还在，但当前文件 AST 已不符合任务；因此不能全部通过。

单引号、注释和普通空白不改变本题的语法树。额外语句、不同常量则改变 AST。这条规则检查指定结构，不能概括为任意程序的语义等价。

## 4. 成功条件来自任务

任务要求运行原脚本，观察 `demo-failure`，并保持文件不变。因此非零退出和对应错误文本是有用证据；文件哈希用于确认没有改写原脚本。

修好再运行会改变任务对象和文件内容。程序能正常退出，也可能不满足这次要求。

## 5. 规则只能支持它实际检查的结论

`echo` 可以带来退出码为0的指定输出；如果模型接着停止，正常停止和有动作也能通过。缺少正确文件时，AST 规则仍会失败。

如果正确文件也已经存在，仅靠“某次输出包含文字”和文件 AST，不能证明那个输出来自执行指定文件。可以进一步让独立评分环境运行实际产物，或检查能可靠归属的执行行为，并相应约束执行环境。不要只比较命令字符串，因为等价命令可能有多种写法。

本课保留一个小规则集，目的是让完成条件、实际证据和判断结果对应起来。扩展行为评分放在任务完成度一课。
