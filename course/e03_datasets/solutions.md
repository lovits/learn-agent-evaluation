# e03 参考解释

1. `curate` 依据审核后的 `(family, intent)` 键去重。改掉 `intent` 后，程序会认为它代表新题意而放行。这说明标签本身必须经过审核，代码不会自动理解任意自然语言句子的语义等价关系。
2. `size-limit` 和 `size-overflow` 同属 `upload-size` 题族。分别放到两侧后，开发集与留出集的题族集合出现交集，`families_disjoint` 会返回 `False`。按单条随机拆分无法保证同族隔离。
3. 不能。哈希只记录来源文档的版本号，无法验证旧参考在新规则下是否仍然正确。资料变更后，需要重新核对题干、引文、参考答案和边界条件，再更新审核结论。
4. 生成器默认把所有候选标为 `pending`。模型生成的参考可能曲解原文数字或条件，题意也可能与已有题目重复，题型标签也可能标错，必须对照原文核对后才能批准入库。
5. 本课的缺证据题明确限定了范围“根据所给 `upload.md`”，在这个范围内账单货币确实未提及，因此合理参考是明确指出资料不足。它有清晰的边界和判据；而未限定范围、导致无法判定对错的题目属于坏题，需要重写。
6. `Golden.expected_output` 保存审核后的参考，`LLMTestCase.actual_output` 保存 Agent 实际运行产出的回答，工具调用过程保存在 `tools_called`。本课专注评测集整理与样本组装，答案质量的评分指标从第 4 课开始接入。
