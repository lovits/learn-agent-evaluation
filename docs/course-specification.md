# 课程目标与制作规范

读者会 Python，了解 RAG 和 Agent。课程通过一个可运行的编程 Agent，讲清怎样准备数据、选择指标、读懂评分、定位错误，再完成版本比较和持续回归。

## 范围

[16课大纲](curriculum.md)保持已确认的顺序。前四课建立成功条件、样本、数据和评分；第5—10课接入 TinyRAG，讲上下文与回答；之后评价工具、任务和会话，最后校准裁判并形成回归。

每课讲透一个核心问题。代码只加入本课必需的增量。工具、权限和记录先从小函数开始；指标课复用已有 Agent，完整项目到最后组合。

## 课文

沿 Learn Claude Code 的实际课文组织：遇到具体困难，给出解决机制，紧接关键代码解释工作原理，再留动手观察的问题。以“问题 → 解决方案 → 工作原理 → 本课变化 → 试一下 → 接下来”为主线，必要细节放在工作原理的子节。

主文给关键片段，完整函数放在代码中。片段与实际行为一致，省略部分明确标示。先解释这几行为什么需要，再解释输入怎样流到结果。

正文不出现安装依赖、配置环境、启动服务或“让 AI 准备环境”等要求。也不放制作记录、成绩表和验收报告。运行验证由制作者完成。每课的 assessment.md 说明样本来源、构造方法、逐样本判断与解释，assessment.json 保留原始证据；真实模型运行、受控反例和软件检查分别标明。教材只保留链接。

源码导读保留 DeepEval 与 Ragas 的官方文档和固定提交源码，沿输入、判据、模型裁决、聚合与边界展开。本课只构造样本时，说明构造与评分的区别；同名指标分别解释。

语言简洁、具体，段落沿问题推进。图只在确实帮助理解结构时使用，图沿用旧版普通 draw.io 的浅色方框、菱形和箭头。按需解释 Agent 循环与独立评测，放在“解决方案”附近；画布紧凑，节点文字由 14 略增至 16，连线由 12 略增至 13，不靠扩大图片提高字号。函数、分支和证据来源须与当前代码一致。构造例子明确说明用途，真实运行结果不编造。

## 目录

`course/` 是课程根目录。每课按需提供 `README.zh.md`、`code.py`、`eval.py`、`cases.jsonl`、`source_walkthrough.md`、`exercises.md` 和 `solutions.md`。辅助模块有实际需要才增加。

`eval_course/` 保存共享运行与知识库基础。`knowledge_base/` 保留可挂载资料。Docker 的执行目录可写，知识库只读；评分独立于被测执行。

## 制作过程

先核对大纲与原始资料，再实现最小场景。使用 PocketFlow-Tutorial-Codebase-Knowledge 从实际代码生成草稿，核对并压缩正文，按 Learn Claude Code 的讲法润色。

随后在 Docker 里实际执行，用独立规则核对任务证据，构造必要反例检查边界。记录区分真实模型运行和受控例子。完成后同步 GitHub 与飞书，并重新读取远端核对正文和代码。
