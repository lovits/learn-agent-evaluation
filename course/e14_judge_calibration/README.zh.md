# e14: 校准 LLM 裁判：用来打分的模型裁判，它自己的判断可信吗？

[e13](../e13_conversation/README.zh.md) → `e14` → [e15](../e15_version_comparison/README.zh.md) → e16

> *“裁判反复给出相同结论，只说明它稳定；结论是否可靠，要拿冻结样本和明确标准逐条核对。”*
>
> **评测层：裁判校准。** 固定候选回答，用独立参考标签统计误接收与误拒绝，再检查篇幅、语言和位置对判断的影响。

## 问题

假设一份回答写对了发布命令，却紧接着说“检查失败也可以先发布”。如果 LLM 裁判给这种回答打了通过，后续所有版本对比都会沿着错误标准往下跑。

模型裁判本身也是概率模型，既可能把违反硬规则的回答放行（误接收），也可能把符合要求的回答判错（误拒绝），还可能受回答长短、语言或展示顺序干扰。在用裁判评估 Agent 版本之前，必须先检验裁判本身。

## 解决方案

先冻结题目、检索资料和候选回答，只更换被测对象为裁判配置。用带来源的参考标签区分开发集与留出集：开发集用来修订裁判规则和提供示例，留出集用来核对修订效果；存在分歧的标注保留待决状态，等仲裁后再入库。

![先定义标准，处理标签分歧，再分开开发与留出材料](https://lovits.github.io/learn-agent-evaluation/diagrams/e14-calibration-flow.svg?v=ca4c2a5f46c7)

裁判逐行输出分数和理由后，按行对齐参考标签，分别计算误接收率、误拒绝率与各类覆盖率，再用语义等价的长短变体、中英变体和 A/B 位置对调检查形式偏差。

![裁判配置分别评分，逐行对齐参考，并保留缺失与偏差观察](https://lovits.github.io/learn-agent-evaluation/diagrams/e14-judge-check-flow.svg?v=623b33e60384)

## 工作原理

### 先定标准，再管标签分歧

本课沿用发布流程任务：命令和执行目录准确，全部检查通过后才能发布，遇到失败必须先修复而不能跳过；当检索证据不足时，应明确指出缺失信息并索要当前规范。

`cases.jsonl` 把候选回答和参考判断放在同一行里：

```json
{"id": "boreal_bad_gate", "reference_label": false, "human_label": null}
```

其中 `reference_label` 存放课程参考标签，`human_label` 预留给独立人工复核。多人标注时，两位标注员应按同一手册独立打分并记录理由；意见一致时直接采纳，出现分歧则交由仲裁决定，未仲裁前保持 `None`。[reconcile](eval.py) 表达的正是这条规则：

```python
return first if type(first) is bool and first is second else adjudicated
```

标注一致后还要复查依据：确认双方读的是同一份任务说明和证据范围，避免两人一起沿用过时口径。

### 冻结候选回答，对比两套 G-Eval 配置

为了把变量锁定在裁判上，本课不重新运行 Agent，直接让两套 DeepEval `GEval` 配置评估同一批冻结候选。

[sample_for](eval.py) 只把问题、实际回答、当前参考和检索资料装进 `LLMTestCase`，参考接受标签留在样本之外，供后续统计使用。

原配置复用第 9 课的 `task_metric`。修订配置 `revised_metric` 调整了 `evaluation_steps`，把硬性失败条件放到前面，同时改用 0/1 二元 `Rubric`：

```text
命令与当前参考矛盾 → 拒绝
检查未通过就发布 → 拒绝
跳过失败项 → 拒绝
其余再看完整性与证据是否充分
```

比较配置时要把 `rubric` 和 `threshold` 一起记录下来。原配置采用 0 至 2 量表，部分正确得 0.5，在 `threshold=1.0` 下同样会判为拒绝。因此分数从 0.5 降到 0 时，最终的通过结论并未改变，需要对照接受判断再下结论。

### 示例严格来自开发集

[development_examples](eval.py) 过滤出开发集中带有布尔参考标签的样本，作为 few-shot 示例写入 `evaluation_steps`：

```python
for c in cases:
    if c["split"] == "dev" and type(c["reference_label"]) is bool:
        # 提取本条样本与标签理由，作为教学示例
```

数据划分按题族隔离：`Atlas` 留在开发集，`Boreal` 和 `Cedar` 划入留出集。同一题的中英变体和长短变体跟随原题族一起划分，[code.py](code.py) 在启动时会校验开发集与留出集没有交集，防止示例泄漏。

修订配置同时改动了评分步骤、量表和开发示例，属于整套配置的对比。如果要单独验证其中某一项改动的贡献，需要做单因素消融实验，并扩展更多独立题族。

### 混淆矩阵与错误率分母

以“参考接受”为正类，把逐行比对结果归入四个格子：

| 参考 | 裁判 | 计数 |
|---|---|---|
| 接受 | 接受 | TP |
| 拒绝 | 接受 | FP，误接收 |
| 拒绝 | 拒绝 | TN |
| 接受 | 拒绝 | FN，误拒绝 |

三项核心统计的分母各不相同：

```text
一致率 = (TP + TN) / 有效比较行数
误接收率 = FP / (FP + TN)
误拒绝率 = FN / (FN + TP)
```

当某个参考类别在当前子集里数量为 0 时，对应错误率的分母为空，程序返回 `None`，避免把缺少拒绝样本的情况误算成零误接收。

### 按行对齐，保留未标注与评分失败

[summarize](eval.py) 先按行筛选带参考标签的数据，再筛选裁判成功返回的行：

```python
labeled = [r for r in rows if type(r["case"]["reference_label"]) is bool]
evaluated = [r for r in labeled if r["result"]["status"] == "ok"]
```

按行过滤能保证每条预测始终对应原来的题目。如果把标签数组和预测数组各自删掉空值后再配对，一旦缺失位置错开，整组统计都会失真。

除了有效行的一致率，汇总结果还会同时报告参考标签覆盖率、人工标签覆盖率、全量评分覆盖率以及已标注行评测覆盖率。未标注样本不参与一致率计算，评分接口报错也单独计数，不会混进拒绝类别。

默认运行模式使用 `fixture_score` 演示混淆矩阵与缺失统计；传入 `--judge` 后会调用真实的 DeepEval `GEval` 裁判，并把每条原始分数、理由和提示词配置保存下来。

### 检查篇幅、语言与位置偏差

形式对照用来观察语义不变时裁判是否会改判。长短变体和中英变体保持与原题相同的核心事实，先确认题目没有限定输出语言，再核对裁判的通过结论是否一致。

位置对照把一对明确的一好一坏候选拼进同一个样本，先按 `(好, 坏)` 放入 Candidate A 与 Candidate B，再交换为 `(坏, 好)`。[pair_metric](eval.py) 用 `GEval` 判分，返回 `1` 代表 A 更好，返回 `0` 代表 B 更好。比较前必须把原始分映射回候选 ID：

```python
winner = (a if result["score"] == 1 else b)["id"]
```

完整代码还会先校验评分状态为 `ok` 且分值属于 `0` 或 `1`，异常情况保留 `None`。如果两次测试的原始分分别是 `1` 和 `0`，但映射后的 `winner` 都是同一个好回答，说明判断保持了一致。

遇到裁判和规则检查的分歧时，也要先核对评分单位和证据范围。[casebook.json](casebook.json) 记录了前两课的两个典型案例：第 12 课的程序契约只检查代码行为，覆盖不到回复里的说明义务；第 13 课的会话指标只看对话文本，看不到磁盘写入结果。先理清指标该看什么，再决定要不要调整裁判提示词。

## 本课组件

| 组件 | 位置 | 作用 |
|---|---|---|
| `sample_for` | [eval.py](eval.py) | 从冻结样本构造 `LLMTestCase`，隔离参考标签 |
| `development_examples` | [eval.py](eval.py) | 仅从开发集提取带理由的 few-shot 示例 |
| `revised_metric` / `pair_metric` | [eval.py](eval.py) | 定义修订版单条裁判与 A/B 位置对照 `GEval` 指标 |
| `reconcile` / `summarize` | [eval.py](eval.py) | 处理双人标注仲裁，按行对齐计算混淆矩阵与覆盖率 |
| `main` | [code.py](code.py) | 校验题族隔离，运行固定统计或 `--judge` 真实裁判与位置对照 |

运行默认模式，查看混淆矩阵与覆盖率统计：

```sh
python -m course.e14_judge_calibration.code
```

动手验证四个问题：

1. 对照留出集的 `fixture_score`，手算 TP、FP、TN、FN 以及各自分母。
2. 查看 `unlabeled` 样本分别影响了哪几项覆盖率指标。
3. 加上 `--judge` 运行两套真实 `GEval` 配置，对比原配置与修订配置在每条留出样本上的分数与通过结论。
4. 观察 `position_pairs` 中两次调用的原始分和映射后的 `winner`，确认判断有没有随位置翻转。
