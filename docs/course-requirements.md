# 课程需求与实施范围

这门课面向会写 Python、了解 RAG 与 Agent 的读者，通过一个逐步长大的编程 Agent 走通完整的评测流程，并读懂 DeepEval 各项指标与评测机制背后的源码原理。

## 最终交付

- 按既定的 16 课顺序递进展开，从最小成功条件走到综合回归门禁。
- 每课提供主教材 `README.zh.md`、可运行代码、源码导读、动手练习与参考解释，并将样本设计与实际运行记录单独存放。
- 结课项目将前面搭好的 Agent、知识库检索与各项判据组合成可运行的持续回归流程，说明如何定位故障、做最小修复并通过门禁复验。
- 全套项目支持在 Docker 中运行，知识库以只读目录挂载。

## 项目与框架职责

| 依据或工具 | 在课程中的作用 |
|---|---|
| Learn Claude Code | 提供递进式的编程 Agent 循环、教材组织结构与工程讲解节奏 |
| Datawhale TinyRAG | 作为课程贯穿知识库检索与上下文组装评测的底层实现 |
| DeepEval | 本仓库唯一采用的评测框架，覆盖样本模型、数据集、自定义规则指标、语义裁判与多轮会话指标 |

能够直接用程序规则核验的条件先用小函数与 `BaseMetric` 落地，需要语义判断的部分再接入 DeepEval 原生指标或 `GEval`。样本构造、指标评分和业务验收在代码中保持职责分离；Agent 仅保留理解评测所需的工具、权限与检索能力。

## 教材组织结构

每课聚焦一个核心问题，主教材沿着以下脉络展开：

1. 问题：从一个具体的任务或失败案例出发，说明现有做法哪里会误判或漏判。
2. 解决方案：给出本课引入的最小机制，并用两张紧凑流程图说明数据流与评分关系。
3. 工作原理：结合关键代码片段解释输入、分支、计算过程与输出边界，完整源码保留在代码文件中。
4. 本课组件（或本课变化）：对照上一课说明新增了哪些能力与模块职责。
5. 试一下：给出可直接执行的命令与几个能区分边界情况的观察问题。
6. 接下来：自然衔接到下一课要解决的新问题。

行文风格沿用 Learn Claude Code 的习惯：具体、直接、顺着数据和代码推进，少用空泛口号与重复小结。安装指南、制作过程记录与成绩单不放进主教材正文；源码导读负责追踪本课调用链以及 DeepEval 官方文档和固定提交源码中的输入字段、判据、裁决结构、聚合公式与空值边界。

## 配图规范

每课主教材嵌入两张原生 SVG 矢量图：一张说明关键运行机制或数据流，另一张说明评测取证与评分逻辑。流程图采用纯 SVG 文本、浅色节点与清晰箭头，保持紧凑画幅：

- 节点文本字号以 `16` 为参考，连线标签字号以 `14` 为参考，避免文字依赖 `foreignObject`。
- 节点写清输入、动作与输出，分支处标明判断条件与对应结果。
- 两张图放在“解决方案”章节附近，源码导读不再重复堆图。
- SVG 源文件随仓库保留；面向飞书等静态阅读场景时，按同尺寸 3 倍像素导出 PNG，保证文字清晰可读。

## 代码与数据原则

每课只加入解释当前知识点所需的代码增量，后续课程直接复用前课已经搭好的循环与工具。规则可直接判定的项目优先使用确定性代码检查；需要自然语言理解时再调用 DeepEval 裁判。

运行过程中严格区分“模型提出了调用”“工具实际执行”“执行成功”和“任务完成”四个层次，完整保留调用参数、工具返回状态与最终产物。接入知识库后，分别保存检索候选、工具回填内容与最后送入模型的上下文；缺少参考或出现接口报错时保留明确状态，不用默认值伪装成业务零分或满分。

## 16 课范围

| 课 | 核心知识点 | 关键实现与观察 |
|---|---|---|
| 01 | 定义成功 | 最小 Agent 循环与 Bash，独立检查运行事件与磁盘文件 |
| 02 | 保存一次运行 | 具名工具、目录权限检查与事件记录，导出 DeepEval `LLMTestCase` |
| 03 | 准备评测数据 | 任务、参考与原文绑定，候选审核、去重与按题族划分开发/留出集 |
| 04 | 给样本评分 | 确定性规则与 `GEval` 语义裁判、量表归一化、阈值与错误状态隔离 |
| 05 | 接通知识库 | TinyRAG 与只读挂载，追踪文档分块、检索候选与模型实际输入 |
| 06 | 上下文相关性与排序 | 区分无关片段占比与有用证据位置，理解 `ContextualPrecisionMetric` 与 `ContextualRelevancyMetric` |
| 07 | 上下文覆盖与召回 | 从参考事实出发核对证据覆盖，理解 `ContextualRecallMetric` 归因口径 |
| 08 | 回答对上下文的忠实度 | `FaithfulnessMetric` 抽取事实与声明，逐条判定支持、矛盾与未提及 |
| 09 | 答案质量 | 分离切题性、事实精度/召回、任务完整性与缺证据合理拒答 |
| 10 | 上下文干扰与故障定位 | 通过受控开关隔离资料缺失、检索漏召回、组装遗漏、过期与冲突 |
| 11 | 工具调用质量 | 核对工具名、参数、顺序与结果，`ToolCorrectnessMetric` 与 `ArgumentCorrectnessMetric` |
| 12 | 任务完成度 | 用独立子进程探针与 `DeliveryContract` 核验交付，结合 `TaskCompletionMetric` 观察边界 |
| 13 | 会话上下文与约束保持 | 追踪多轮约束新增、覆盖与取消，对比 `KnowledgeRetentionMetric` 与 `ConversationCompletenessMetric` |
| 14 | 校准 LLM 裁判 | 标注分歧仲裁、混淆矩阵、误接收/误拒绝与篇幅/语言/位置偏差检验 |
| 15 | 比较两个版本 | 固定同题配对比较、按题型分层排查、题族 Bootstrap 与调用成本核算 |
| 16 | 综合项目与持续回归 | 串联 Agent、TinyRAG 与各项判据，建立分项硬门禁与待复核队列 |

上下文链路评测集中在第 5 至 7 课，第 8 至 10 课接着排查上下文对回答质量的影响。评测数据集的构建规则在第 3 课确立，后续课次在此结构上扩充对应样本。各课详细知识点与源码依据见[完整大纲](curriculum.md)。

## 验收与质量标准

每一课完成时需同时满足以下条件：

- 讲解范围与[完整大纲](curriculum.md)一致，关键代码片段与实际可运行脚本完全吻合。
- `assessment.md` 与 `assessment.json` 如实记录样本构造方式、Docker 实测结果、接口报错与单元测试覆盖范围，将构造算例与真实模型调用分开标明。
- 主教材嵌入的两张 SVG 在本地阅读器与 GitHub 页面均能正确加载和渲染，字号与画幅符合规范。
