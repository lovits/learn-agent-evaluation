# e06: 有用的资料，排在了哪里？

## 问题

上一课能追到模型收到的资料。现在问：Atlas 发布前要运行什么检查，什么条件下才能发布？

返回列表中即使有发布规范，也可能夹着日志期限和认证说明。如果发布规范排在后面，有限的上下文预算可能还没选到它。只问“有没有找到”，还不足以评价这份列表。

需要分清两件事：返回的片段有多少有用，以及有用片段排得多靠前。

## 解决方案

复用 TinyRAG 取得候选，固定问题、参考和片段内容。按“能否帮助回答参考中的命令与发布条件”给片段标 0/1，再保持标签不变，移动位置。

![固定标签后分别计算普通精度与列表 AP](https://lovits.github.io/learn-agent-evaluation/diagrams/e06-ranking-flow.png)

然后用 DeepEval 原生指标观察模型怎样判定。逐片段判断和逐陈述判断分别保存，分数连同单位一起解释。

## 工作原理

### 先规定什么叫有用

[题目与标签](cases.jsonl) 把提供测试命令、发布条件的规范标为 1，不能提供这些内容的认证和日志说明标为 0。这是为本题核对的教学标签，不是“只要提到 Atlas 就相关”，也不是独立人工金标准。

[prepare](code.py) 核对文档哈希与候选编号，再冻结当前列表。资料或候选集合改变，需要重新审核标签。接下来重排只是控制条件，不声称检索器真实返回过每一种顺序。

### 普通精度看比例，AP 还看位置

设相关标签为 1，无关为 0。普通精度很直接：

```text
precision = 相关片段数 / 返回片段数
P@i       = 前 i 位相关数 / i
```

下面是手算例子：

| 标签顺序 | 普通精度 | 相关位置的 P@i |
|---|---:|---:|
| [1,0,0] | 1/3 | P@1 = 1 |
| [0,1,0] | 1/3 | P@2 = 1/2 |
| [0,0,1] | 1/3 | P@3 = 1/3 |

普通精度只数数量，看不到位置。列表 AP 在每个相关位置取 P@i，再对这些值平均：

```text
list_ap = Σ(当前位置标签 × P@i) / 本列表相关数
```

[ranking](eval.py) 的核心循环与这个式子对应：

```python
for position, label in enumerate(labels, 1):
    cumulative += label
    weighted += label * cumulative / position
```

`label=0` 时不加入 AP 分子；`label=1` 时加入当前位置之前的相关比例。最后除以 `relevant`。上面三个例子各有一条相关项，因此 AP 分别为 1、1/2、1/3。

如果有两条相关项，如 `[1,0,1]`，AP 是 `(1 + 2/3) / 2`。不能只看最后一位，也不能把所有位置的 P@i 不加区分地平均。

### 高 AP，也可能带着尾部噪声

把 `[1,0,0]` 变为 `[1,0,0,0]`，普通精度从 1/3 降为 1/4，AP 仍为 1。相关项之前的位置没变，尾部噪声没有进入 AP 求和。

这里 AP 的分母是当前列表中被判相关的项数，**不是知识库里所有应该找到的证据数**。只返回一条有用资料也可能得高 AP，所以它不能证明没有遗漏。下一课再评价覆盖与召回。

空列表在本课算式中记为 `None`；非空但全不相关时记为 0。SDK 的聚合函数可能另选空值约定，[源码导读](source_walkthrough.md)分别说明。

### 语义标签由谁判断

固定标签适合隔离排序影响。真实资料中，要按问题和参考判断是否有用，可以调用 DeepEval 的 `ContextualPrecisionMetric`：

```python
sample = LLMTestCase(
    input=case["query"],
    expected_output=case["reference"],
    retrieval_context=[p["text"] for p in orders[name]],
)
```

本课测检索器，不生成新回答。这个固定 SDK 的指标路径不读取 `actual_output`，因此保留为空。

`judge_precision` 将有序字符串片段交给裁判，取得各项 yes/no 与理由，再由 SDK 按列表 AP 聚合。代码还核对裁决数量：三个字符串应对应三条裁决，少一条不能自动补成 no。接口、结构或对齐错误保留空分数。

两次调用即使只有顺序不同，模型也可能改变判定。要单独观察算式的排序效应，就固定标签；要观察真实裁判，就保留每次自己的原始裁决。

### 片段相关，与陈述相关

`ContextualRelevancyMetric` 不需要参考答案。它从每个片段提取陈述，逐条判断与问题是否相关，再计算：

```text
相关陈述数 / 全部有效陈述数
```

假设一段资料中有一条有用陈述和三条无关陈述。片段级可以判它有用，陈述级比例却只有 1/4。更多陈述会对这个比例贡献更多权重，并非每份文档等权平均。

三个相近名称要这样读：

| 指标 | 判据与单位 | 聚合 |
|---|---|---|
| DeepEval Contextual Precision | 问题与参考；逐片段是否有用 | 相关位置的 P@i 均值 |
| DeepEval Contextual Relevancy | 问题；逐陈述是否相关 | 相关陈述比例 |
| Ragas Context Precision（有参考） | 问题与参考；逐片段是否有用 | 同类列表 AP |

Ragas 在这里用于理解判据与源码，没有再接入评分。即使聚合相近，提示词和判断过程不同，也不能把两个框架的数值当成同一次测量。

### 另外两个排序视角

`ranking` 还给出 RR 与二元 NDCG，作为对照：

- RR 是第一个相关项的位置倒数；多个查询的 RR 平均才叫 MRR。`[1,0,1]` 的 RR 已为 1，后面的排序不影响它，AP 仍会用到第三位。
- NDCG 将位置 i 的相关标签除以 `log₂(i+1)`，加总后，再除以同一批标签理想重排的值。它用折扣观察有用内容是否靠前。本课只用 0/1 标签，不引入多级相关度。

这些视角都以当前列表为范围，不能替代参考事实的覆盖检查。
