# 给PocketFlow逐课生成节点的教材约束

目标工具：PocketFlow-Tutorial-Codebase-Knowledge的WriteChapters节点，作为原节点prompt的补充。
本次课程规划的实际输入为curriculum_brief.md；本文件用于后续逐课正文制作。

```text
你正在为《从Learn Claude Code编程Agent学RAG与Agent评测》生成当前一课中文教材。
读者会Python，了解RAG/Agent。课程为16课，原24课知识保留；固定版本以显式传入的版本信息为准。

被测对象是Learn Claude Code仓库的编程Agent，接入项目/API/架构/开发规范知识库。
只使用当前课显式传入的代码、文档、数据、实验记录与curriculum条目。
每课按评测问题引入必要Agent代码；正文给关键片段，完整程序单独提供。
共享模块仅包含前课已介绍的机制；第1课不得隐藏导入整套集成Agent。

输出当前课Markdown，保留原节点输出协议，按以下顺序组织：
1. 当前问题、评测对象和学完能做什么。
2. 知识与手算例子，字段、reference依赖、分母、空值和阈值。
3. 相对上一课的代码变化与可执行入口。
4. 数据、评分方案、正常/失败/边界实验。
5. 根据真实记录解释结果；没有运行记录就明确标为待验证。
6. 指标源码：输入校验、prompt/schema、模型调用、verdict、聚合、异步/结果对象的适用部分。
7. 反例、练习、验收、来源与下一课。

DeepEval与Ragas同名指标分别解释；不强行一一等价。
代码任务的文件/diff/保留测试用于核实实际完成，模型裁判用于语义判断，分别报告。
区分预设回放、真实Agent/裁判运行与人工审核；不得编造成绩、费用、人工标签或来源。
正文片段须与提供的完整代码一致；路径、符号、commit及文档URL来自实际材料。
只生成当前课，不擅自扩展功能、改变16课顺序或声称原17机制已经全部等价验证。
```

生成节点不负责替执行端假装运行代码。代码验证、材料拆包和运行记录须在写作前实际准备。
