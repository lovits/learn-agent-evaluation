# e09: 版本比较 — 先配对，再看均值

[课程](https://github.com/lovits/learn-agent-evaluation/blob/main/README.md) · [上一课](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e08_datasets/README.zh.md) · [下一课](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e10_tool_evaluation/README.zh.md) · [源码导读](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e09_comparison/source_walkthrough.md)

> 比较同一任务的变化，才能讨论改动有没有帮助。

## 多返回一篇文档，会更好吗

我们只改检索数量：基线取一篇，候选取两篇。候选可能补齐认证文档，也可能增加无关内容与延迟。

如果两个版本做的是不同题，或者使用不同 reference，即使均值上涨，也无法知道差异来自哪里。本课不增加 Agent 能力，把代码放在运行循环外面，固定条件并整理配对结果。

## 只让一个因素变化

[`manifest`](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e09_comparison/code.py) 保存任务、源码和文档版本，同时声明比较条件：

```python
"only_changed_factor": "retrieval_limit_k",
"k_values": [1, 2],
"repeats": REPEATS,
"minimum_effect": 0.1,
"model_sampling_seed": None,
```

两个版本使用同一查询、初始文件、模型入口、提示词和评分函数。分发器只替换 `search(..., limit=k)`，其他工具不变。

模型仍有抽样波动，所以对同一任务重复执行，并交替运行顺序。重复观察能帮助理解波动，但一个任务多跑几次，仍然只有一个任务。

## 每次先检查实际产物

Agent 写出 `answer.json` 后，`inspect` 重新读取字段、类型与来源。只把正常结束且满足合同的运行标记为通过。

Ragas 原生 `@experiment` 驱动数据行，DeepEval `LLMTestCase` 保存任务、产物和配置。框架组织运行，具体成功条件由本课的文件规则判断。

## 重复先合并，版本再相减

手算一个任务：基线两次为 `[0, 1]`，候选两次为 `[1, 1]`。

```text
基线任务分 = 0.5
候选任务分 = 1
配对差值   = 1 - 0.5 = 0.5
```

[`paired_rows`](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e09_comparison/statistics.py) 按任务和版本分组，要求重复编号齐全，拒绝重复编号。不能把异步返回的两个列表直接 `zip`，因为完成顺序未必一致。

再按单跳、多跳等类别汇总。总体改善时，关键类别仍可能退步，因此选择规则同时检查分层。

## 开发决定先保存，留出结果后打开

开发集用来选择候选。这里的示例政策是整体改善至少0.1，且已观察分层没有退化。决定先写盘，再执行另一个任务族的留出评价。

留出前重新比对条件：

```python
if decision["manifest"] != frozen:
    raise ValueError(
        "Code, data or protocol changed after selection; start a new experiment"
    )
```

代码、数据或标准已经变化，旧决定就不再适用。看过留出结果后继续调参，等于把它用成了新的开发集。

## 区间的抽样单位是什么

同族题共享文档和模板，结果可能一起变化。`family_bootstrap` 先算题族差值，再对题族有放回重采样，取 percentile 区间。

```python
rng = random.Random(seed)
draws = sorted(mean(rng.choices(values, k=len(values))) for _ in range(resamples))
```

增加重采样次数，只让数值模拟更稳定，不增加真实任务数。只有一个题族时，本课不报告区间；很少的公开题族也只能用来理解方法。

重复评分同一回答观察的是裁判波动，重复执行 Agent 观察的是应用波动，要分开处理。

## 质量之外还要看代价

质量、墙钟时间、调用数和 token 分别记录。并行工具时长之和可能超过墙钟；缓存 token 不能重复加到输入总数。模型型号或单价不清楚时，费用保留未知。

先确认候选确实满足任务，再讨论这点改善是否值得增加的代价。

## 试一下

只改变 `k`，对照单跳和组合问题的实际检索内容。哪一类更可能因第二份文档获益？

再想一个均值上涨、关键类别下降的例子。把能否接受候选的规则写在看结果之前。

## 变化只发生在检索分发处

`limited_dispatch` 检查固定查询，在相同文档副本上以 `limit=k` 搜索，其余请求仍交给前课。`execute_trial` 运行真实 Agent，然后读取 `answer.json`，保留逐条判定。

manifest 保存实际源码、任务和文档哈希。开发阶段 `choose` 只读取开发结果，冻结后才能进入 holdout。课程公开任务用于理解协议，正式比较还要另备代表性任务。

## DeepEval：把配置与输出关联

[参数优化指南](https://deepeval.com/guides/guides-optimizing-hyperparameters) · [evaluate.py](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/evaluate/evaluate.py)

批量入口校验输入、按配置选择同步或异步执行，再把 `hyperparameters` 关联到运行。它不会自动检查两个实验的样本配对，也不会替调用者计算统计区间。

本课使用 `LLMTestCase.metadata` 保存版本和运行信息，文件合同给出规则分。源码阅读中的批量入口与本课的直接调用应按接口区分。

## Ragas：按完成顺序收集结果

[实验概念](https://docs.ragas.io/en/stable/concepts/experimentation/) · [experiment.py](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/experiment.py)

`@experiment` 返回 `ExperimentWrapper`；`arun` 为数据行创建任务，通过 `asyncio.as_completed` 收集结果。因此每行必须有 `case_id/k/repeat`，不能依靠列表位置配对。

固定实现可能警告后跳过异常行或 None 返回值。本课检查运行结果完整性，遗漏时停止比较，避免分母缩小。

[Dataset](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/dataset.py) 和 [InMemoryBackend](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/backends/inmemory.py)负责数据载体。内存后端的保存不等于跨进程文件持久化，JSON 写入由本课另行完成。

## 配对差值怎样形成

`paired_rows` 先检查两个版本的重复编号相同且没有重复，再求任务内部均值，最后计算候选减基线。`summarize` 保留逐题差值、分层和代价。

一次执行中的业务字节数与统计样本量没有关系。同题重复也不能当成多个独立用户需求。

## 为什么按题族重采样

`family_bootstrap` 使用标准库实现 percentile 方法，先求族均值，再抽族。题族只有一个时返回空区间；族数量少时，区间只描述已有材料，无法保证未知任务的表现。

它与[配对 bootstrap](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)使用同一索引保持配对的思想一致，但没有调用 SciPy，也不是 BCa。族大小不同时，应先明确按族还是按题加权。

`repeat_judge` 对固定回答重复评分，不参与版本选择。应用与裁判的延迟、请求和 usage 也分别记账。
