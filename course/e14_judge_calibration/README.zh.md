# e14: 评分器自己判得准吗？

[e13](../e13_conversation/README.zh.md) → `e14` → [e15](../e15_version_comparison/README.zh.md) → e16

> 固定回答，检查裁判的误判与适用范围。

## 问题

回答给对了发布命令，却说“检查失败也可以发布”。裁判若仍判通过，后面的版本比较就会沿着错误标准走。

同一个裁判反复给出相同判断，只说明它稳定。还要问：这个判断符合明确的业务标准吗？

## 解决方案

先固定问题、资料和回答，再准备有来源的参考标签。开发材料用于修订裁判，留出材料用于核对；有分歧的标签保留待决。

![先定义标准，处理标签分歧，再分开开发与留出材料](https://lovits.github.io/learn-agent-evaluation/diagrams/e14-calibration-flow.png)

保留每条裁决，分别统计误接收、误拒绝与覆盖率。另用语义等价的长短、中英回答和位置对照，观察判断是否受形式影响。

![裁判配置分别评分，逐行对齐参考，并保留缺失与偏差观察](https://lovits.github.io/learn-agent-evaluation/diagrams/e14-judge-check-flow.png)

## 工作原理

### 先说清什么叫可接受

本课继续评价发布流程：命令和目录正确，全部检查通过才发布，失败先修复、不跳过。证据不足时，应保留缺失事实并索取当前规范。

`cases.jsonl` 同时保存候选回答和参考判断：

```json
{"id": "boreal_bad_gate", "reference_label": false, "human_label": null}
```

reference_label 是课程作者构造的教学参考，human_label 留空。它们不能被称为独立人工共识。

真实标注时，两人先按同一手册独立判断、保存理由；不一致时明确仲裁，未仲裁保留空值。[reconcile](eval.py) 只表达这一步：

```python
return first if type(first) is bool and first is second else adjudicated
```

两人意见一致也不保证标准正确。需要核对标签是否依据同一任务、同一证据范围，而非只追求一致。

### 冻结回答，才知道在比较谁

本课不重新生成 Agent 回答，只让两个 DeepEval G-Eval 配置评价同一批候选。

[sample_for](eval.py) 只提供问题、实际回答、当前参考和检索资料。参考接受标签不进入待评分样本；它留给之后的对照统计。

原配置复用第9课裁判。修订配置将硬失败放在部分正确之前：

```text
命令与当前参考矛盾 → 拒绝
检查未通过就发布 → 拒绝
跳过失败项 → 拒绝
其余再看完整性与证据是否充分
```

量表与阈值也要保留。原量表的部分正确分，即使不是0，在通过阈值为1时仍可能被拒绝。不要把“分数下降”直接解释成“误判减少”。

### 示例只能从开发集来

[development_examples](eval.py) 只选开发行：

```python
for c in cases:
    if c["split"] == "dev" and type(c["reference_label"]) is bool:
        # 提取本条样本与标签理由，作为教学示例
```

Atlas 用于开发，Boreal、Cedar 留出。同题的中英、长短变体跟随题族，程序禁止题族跨集合。

这次同时调整了步骤、量表与示例，比较的是整个裁判配置。即使出现变化，也不能单独归因于某一句提示词。这些题族还共享发布模板，不能把小型留出对照当作广泛泛化证明。

### 混淆矩阵先确定正类

这里以“参考接受”为正类：

| 参考 | 裁判 | 计数 |
|---|---|---|
| 接受 | 接受 | TP |
| 拒绝 | 接受 | FP，误接收 |
| 拒绝 | 拒绝 | TN |
| 接受 | 拒绝 | FN，误拒绝 |

对应的分母不同：

```text
一致率 = (TP + TN) / 有效比较行数
误接收率 = FP / (FP + TN)
误拒绝率 = FN / (FN + TP)
```

不存在相应参考类别时，错误率没有分母，保留 None。没有拒绝样本，不等于已经证明误接收率为0。

### 评分失败与未标注要留在视野里

[summarize](eval.py) 按同一行的标签与裁判结果对齐：

```python
labeled = [r for r in rows if type(r["case"]["reference_label"]) is bool]
evaluated = [r for r in labeled if r["result"]["status"] == "ok"]
```

不要分别删除标签数组、预测数组中的空值再配对，位置可能已经错开。

未标注不能进入一致率，评分失败也不是一个拒绝标签。除了有效行的一致率，还要分别报告参考标签覆盖、人工标签覆盖、所有行评分覆盖和已标注行评测覆盖。否则只剩少量容易样本时，结果仍可能显得很好。

默认运行使用 fixture_score 演示统计，其中故意放入误接收、误拒绝和空评分；它不是模型输出。加 `--judge` 才执行真实裁判，原始分数、理由和配置分别保存。

### 形式变了，含义有没有变

长短与中英变体保留相同事实。先确认任务没有限制语言，再比较接受判断；如果长回答多了错误，就不能把差异都叫作篇幅偏差。

位置例子把同一对候选交换到A、B。这个受控 G-Eval 的1表示A更好，0表示B更好，比较前要映射回候选ID。

```python
winner = (a if result["score"] == 1 else b)["id"]
```

片段省略了有效状态与0/1检查，完整实现保留未决结果。这个小例子限定一好一坏，不能照搬到平局或模棱两可的任意回答。

原始分从1变0，可能只是同一好答案从A移到了B。一次对照没有翻转，也不证明不存在位置偏差；还需要更多题族和重复观察。

### 改提示词，也要核对它究竟改了什么

Ragas 的 align 思路是使用带标签的数据分析分歧，再调整提示或示例；相关实现可以把训练行加入动态 few-shot，不等于训练基础模型权重。

语言 adapt 默认主要翻译示例，指令是否翻译要看配置与具体接口。翻译后的否定、术语和标准仍需验证，不能仅改语言标记就宣布公平。本课只读 Ragas 文档与源码，实际评分继续使用 DeepEval。

[前课案例](casebook.json) 还提醒我们先检查指标选择：程序契约通过未必覆盖说明义务，语言层会话分低也不能否定真实文件。遇到分歧，应先理清标准和证据，再决定是否修改裁判。

## 本课变化

只增加冻结候选、开发示例、参考对照统计与必要的形式对照。Agent 和知识库不增加能力，未将构造标签写成人工评测结果。
