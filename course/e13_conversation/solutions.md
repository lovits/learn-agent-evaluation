# e13 参考解释

[练习](exercises.md) · [教材](README.zh.md)

1. 路径（`summary.md`）与新正文由 `u2` 覆盖生效，40 字限制（`max_chars`）由 `u2` 取消并移入 `superseded`；中文要求（`language`）与不修改 `policy.txt` 的保护条件（`preserve`）仍从 `u1` 保留。增量修改只作用在指定的键上，未改动的旧约束继续有效。
2. `full_old` 的首次 `model_inputs` 已经包含 `u2` 的完整更新，排查重点应放在模型为何忽略最新约束、依然调用旧路径；`stale_memory` 的首次输入里只有过期摘要，排查重点则应放在摘要为何遗漏修改以及 Agent 是否具备读取归档的恢复入口。另外，字符串出现只说明文本进入了上下文，并不能自动等同于模型理解了覆盖关系。
3. `tail_only` 缺少可执行的目标信息，主动澄清可以避免凭空猜测路径或编造正文，但用户交付任务确实尚未完成。把安全边界合规、对话沟通合理性与最终交付状态分开记录，才不会把正当澄清误标成执行故障。
4. `read_file("conversation.json")` 执行后，真实工具输出回填进消息队列，最新约定才在下一轮的 `model_inputs` 中进入模型上下文。`archive_recovery` 通过两批调用体现了这一先后顺序，真实模型运行时也必须按轮次核对每份输入快照。
5. `active_requirements` 遇到 `drop: ["max_chars"]` 时会从当前状态字典移除该键，后续 `check_delivery` 便不再执行 `length_limit` 检查。如果沿用旧的 40 字限制，就会把按 `u2` 新约定写入的长正文误判为失败。
6. 在 `Knowledge Retention` 中，`yes` 代表遗忘或矛盾，`no` 才是通过，分母是具备前置知识且获得有效裁决的 `assistant` 单位数；在 `Conversation Completeness` 中，`yes` 代表意图满足，分母是抽取出的有效用户意图数。若遇到空单位或缺失裁决，应按 `not_applicable` 或 `error` 单独处理。
7. 前期简单确认回合拿到的通过裁决会稀释最后一步执行失败对均值的影响。排查与门禁判定时应保留逐回合裁决，同时把基于最新有效约束的独立磁盘文件检查作为硬条件，避免用会话平均分掩盖关键交付失败。
8. 不能。本课的 `current` 摘要是控制输入完整性的预设条件，并没有测试任何自动摘要器。要评估自动摘要器，需要固定同一份原始历史，让摘要器实际生成摘要后检查关键事实遗漏、过期覆盖错误与来源标注情况，并与完整历史条件做同题配对对比。
