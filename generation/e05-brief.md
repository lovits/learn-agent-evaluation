# 第5课编写要求

为已完成前四课的Python读者写Faithfulness：回答是否忠于本次检索证据。沿用Learn Claude Code的小步组织：只新增独立评分，Agent不扩展、不重新执行。从“文档没说自动重试，回答为什么写了三次”引入，逐步讲claim拆解、支持/矛盾/信息不足、NLI、两个原生SDK、手算聚合、空声明、证据改版、真实Agent记录再评。约3000至4500中文字，具体自然有耐心，不虚构亲身经历，不机械小结或空泛升华。

素材是code.py、eval.py、cases.jsonl、run_summary.md、源码导读与练习。以真实摘要为准，不编造分数和调用数。完整代码链接单独提供，正文仅给必要片段并标明省略。不要Mermaid或未渲染LaTex。

关键事实：
- 五条受控回答：supported、unmentioned、contradiction、mixed、no_claim；另有同回答的evidence_v2和第4课真实Agent的recorded_agent，共七条。第4课真实原始回答和当次search_knowledge文档快照重新评分，不把它说成新Agent运行。
- Faithfulness相对证据，不等同外部正确性、完整性、切题或任务成功。NLI三种关系是理解工具，SDK实际裁决schema不同。人工annotation不交给裁判作为答案。
- DeepEval固定4.3.4先抽truths再抽claims再判verdict。truths也是模型结果；原文遗漏会影响判定。默认yes+borderline占有效verdict比例，开启penalize仅yes。手算yes/borderline/no默认2/3、惩罚1/3；只对实际verdict重聚合，不新调用模型。未说的内容不自动等于矛盾。阈值0.7为教学约定，strict_mode=False，include_reason=False省去总结但保留逐声明reason。同步与异步入口说明见源码导读。
- DeepEval共享score_qag_verdicts空verdict默认1，不表示任务答对；Ragas collections按binary支持比例，无statements/无判定返回NaN。非空Thanks!是否拆为空以模型实测为准，不能强迫输出预设标签。Ragas空字符串response直接报错，与非空但无声明不同。
- Ragas先StatementGenerator再NLI，两步schema原始结果都记录；InstructorBaseRagasLLM适配复用第4课，DeepEvalBaseLLM适配复用第3课，不改SDK算法。不同SDKclaim数量可能不同，不能仅凭高分比较优劣。
- 原生NaN转JSON null、status=undefined_nan、passed=null；异常是status=error并非零退出；有效0分正常保存。缺确切型号、费用和logprobs不编造。
- 同一路径的1048576改成2097152并更新sha256，用同一回答对比。evidence_key按id+可信加载器sha256元数据（含顺序）识别证据；变化时拒用旧标注。不声称是防篡改验证。新版本是受控材料，不代表实际服务器配置变了。
- 初次宿主机裁判入口未启动，14项连接错误、0次真实模型调用，失败报告留存；启动后才有成功实测。准确记录实际请求数，生成器调用另算。
- 当前材料是小型开发教学实验，不声称严格盲测或通用可靠性。下一课处理相关性、正确性、完整性和拒答。

运行命令：
宿主机保持 python3 tools/judge_bridge.py 运行（复用本机Codex已登录，凭据不入容器）。另开终端：
```sh

docker compose run --rm -T --entrypoint python course -m lessons.e05_faithfulness.eval
```
报告写runs/e05-evaluation.json，会覆盖同名文件；比较前另存。教材example_report.json为固定真实记录不受重跑覆盖。阅读用docker compose up -d，http://localhost:8765/lesson5。

正文给七种结果对照，区分有效低分、未定义与调用错误；给手算、证据变更、原始快照再评等练习及答案链接。官方文档与固定源码URL来自source_walkthrough.md。最终验收看原生指标运行无错误、原始裁决可核对、旧证据标注被拒用，而不是所有样本都高分或每次调用数固定。
