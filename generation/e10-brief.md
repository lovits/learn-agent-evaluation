# 第10课：工具、参数与MCP，分开看才评得准

按references/textbook-writing-standard.md，像Learn Claude Code一样从具体困难进入，以真实短代码解释机制。正文约2500至3500中文字，二级标题只有“问题、解决方案、工作原理、相对上一课的变更、试一下、接下来”。工作原理6个加粗步骤，每步5至15行现有源码摘录，注明局部省略；完整code.py、mcp_tools.py、metrics.py、eval.py单独链接，不贴完整Agent，不发明字段或函数。详细公式/调用链/矩阵放源码与结果附页，知识点不能丢。

问题：同一个计算脚本修好，可能内置搜索，也可能MCP检索；名字对、参数对、顺序对、运行放行、文件正确需要分别观察。从calculate.py里unit_price=7，而挂载合成规则要求quantity=6、unit_price=8进入，真实结果48。它仍是编程Agent，不是问答机器人。

解决方案：复用第4课Agent循环、文件工具、权限和轨迹，仅增加进程内模拟MCP发现/分发及独立工具评分。上游s14本身也用模拟server，不声称实现MCP线协议。配现有图![动态工具池](images/dynamic-tool-pool.png)，同PNG给放大链接。图只画放行路径，拒绝直接回循环。模型在宿主机只返回动作，其他工具代码在Docker真实执行；宿主配置策略不是server声明自行授权。

工作原理6步：
1. run_case中的model闭包每轮pool.assemble→保存tool_snapshots→call_model(messages,tools)，同一e04 agent_loop传tool_dispatch=pool.dispatch。首轮只多connect_mcp，没有mcp__docs__search；动态工具定义交给实际宿主机桥返回受限JSON动作。
2. connect只连接配置的docs，把server工具定义与handler存入client。assemble把inputSchema转换input_schema，名字mcp__server__tool，规范化冲突/64字符限制。已有原生5工具和knowledge搜索仍保留。不要提前贴完整ToolPool，用真实局部代码解释下一轮工具可见性。
3. dispatch解arguments_json，取固定client与raw绑定；HOST_POLICY决定allow或confirm，server的description/readOnlyHint不授权。批量默认拒绝未批准。缺参、错类型、多参返回工具错误；参数tool不能改派handler。其他工具交已有dispatch，不改变Agent基础循环。示例真实MCP输入输出来自挂载知识库，不是伪造搜索结果。
4. 原始events到评分样本：名字、原始参数、顺序、权限、结果分别保留。11条micro_traces是构造未执行控制，2条真实轨迹三动作教学投影带source_span，不是整任务质量。业务验收接受edit/write不同路径，读取实际文件/已有执行证据；直线整数乘法小合同不证明任意Python等价，不重新运行任意生成程序。
5. 用真实native调用片段解释DeepEval ToolCorrectness默认名字覆盖，加入INPUT_PARAMETERS后并集键比例；ordering加权LCS/预期数，exact严格列表。RagasToolCallAccuracy strict完整名字序列，flex排序但重复长度仍失败；参数只遍历reference键用str比较，额外参数/类型可能被放过。F1按完整(name,args)集合，不罚相同重复或换序。正文围绕“重复一次F1仍1、严格序列0”或“多余参数匹配分高而handler拒绝”一个短算例，不列完整矩阵。空/空RagasF1=0而Accuracy=1，附页保留；默认分不能代替业务合同。available_tools存在才有DeepEval模型选择分，取min；本课真实运行该分支，非模型规则配置另记。
6. ArgumentCorrectness是语义判参数，原生Verdicts→yes比例，需要正确input。首轮真实MCP核心投影删了连接/文档却保留完整任务，裁判误给2/3；保留首轮，修订decision_contexts按model span恢复当时tools+过去messages，绝不注入未来结果，再实际评分。只改评分协议，不改文件或重跑Agent。真实最终9个非空决策轮的11工具调用均yes；自动判断非人工标签。无调用ArgumentCorrectness=1且0次请求属无参数可判，不能说完成。正文给pending回填或本轮输入短代码，详细trace ownership/nativeQAG/数量核对留源码。

实际证据以run_summary为准。正式两版业务合同都过，MCP版明确多了一条路由要求，因此不是受控性能因果比较。初次启用MCP但普通任务仍选builtin的记录已归档，能力任务明确后重新真跑，不篡改旧轨迹。避免把91分数/13请求当主线，不写未知费用型号。两轮评分协议不同，不能把升分称为Agent改善。
