# PocketFlow 课程规划约束

目标：根据显式提供的材料包，制定《从 Learn Claude Code 编程 Agent 学 RAG 与 Agent 评测》的16课大纲和制作计划。
读者会Python，了解RAG/Agent；希望掌握实际设计、运行、诊断、比较评测的能力与关键源码。
被测对象固定为 Learn Claude Code 编程 Agent。知识库为项目/API/架构/开发规范文档。
每课只按评测问题引入代码，正文给必要片段，完整代码可执行；不得第1课贴整套集成Agent。

lesson-contracts.json 给定16课主题、保留的24课知识、评测对象、代码增量、实验、验收与来源。
原24课清单是完整性约束；所有知识必须保留于新课小节/练习。agent-capabilities.json给出原17机制归属。
该归属是计划，不能声称17机制已迁移或等价验证。简化重复实现与启动方式，保持功能契约。
只使用材料包能证明的源码/官方文档事实；符号和路径以输入为准，不编造调用关系或实测结果。

本轮只做课程设计。现有实现为s07 Faithfulness回放样章；新编程Agent课程尚未实现。
旧样章作为新第5课评分机制素材，后续改用编程知识案例并接入真实Agent输出。
真实SDK加预设输出只验证评分管线，不能描述为模型准确率实验；真实Agent/裁判需分别配置接口。

节点协议：
- IdentifyAbstractions：将课程主题作为教学抽象，必须恰好16项，按lesson-contracts的编号和名称；description概述评测、知识、增量、实验与验收；保留原YAML字段及真实file_indices。
- AnalyzeRelationships：给出知识先修与评测数据依赖，所有主题都参与；这些关系不是未经验证的源码调用边。
- OrderChapters：保持已核对的16课先修顺序，以原YAML索引协议返回，每项恰好一次。
- 课程写作节点：输出中文Markdown计划，先解释Learn Claude Code教学方式，再列两框架评测/数据能力，再给16课逐课卡片与执行计划。不得生成16课全部正文或声称已执行计划实验。

逐课卡片必须包含：标题、评测什么、学哪些知识、引入哪些可执行Agent代码、做什么实验、怎么验收、DeepEval/Ragas文档与源码依据。
每课引用至少一条材料给出的官方来源，源码用固定commit的GitHub URL或正确的输入路径。
通过外部文件/diff/验收测试核实代码任务；通过模型判断评语义，两者分别报告。
数据生成、划分、审核、裁判校准、统计不确定性、回归、错误与成本不能从大纲删掉。
安全/SQL/摘要/多模态/语音/基础模型基准等保留能力索引与附录范围。
源码分析贯穿输入校验、prompt/schema、调用、verdict、聚合、异步与结果对象，不留到最后才读源码。

计划应分阶段列出输入、产物、通过条件，明确Docker中的知识库只读挂载、可写练习目录与结果目录、
验收数据独立保管、模型与裁判配置、回放/真实模式、固定版本和GitHub回归。
先制作第1–2课与编程版第5课验证组织方式，再逐批扩展，不以一次性输出完整Agent替代递进教学。
