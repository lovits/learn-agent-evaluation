## 每课制作顺序

1. 明确评测对象、前置知识、成功条件、正常/错误/边界任务。
2. 核对Learn Claude Code与DeepEval/Ragas的文档、固定源码和当前API。
3. 只加入本课需要的可运行代码；复用已经讲过的能力。
4. 在Docker执行适用实验，保存原始轨迹、外部状态和评分。文档改写保留历史结果，新的行为另实测。
5. 当前课材料包交给PocketFlow原版写作节点；生成原稿和凭证分开保存。
6. 技术审校后用humanizer通读；正文采用六部分和分步短代码，详细结果与源码放附页。
7. 检查Docker阅读器、链接、代码与适当测试，完成GitHub CI；同步飞书并回读。

正文写作标准见[统一标准](../references/textbook-writing-standard.md)，新标准改写记录见[阶段验收](course-revision-validation.md)。完整课题与范围继续以[16课规范](course-specification.md)为准。

## 综合项目完成条件

按上游17项能力清单逐项验证工具、权限、hook、计划、子任务、skills、上下文压缩、记忆、任务依赖、后台、调度、协作、MCP、集成、工作流续跑和目标停止。给出实际集成代码、模块关系和完整调用链，完成正常/错误/边界任务、独立验收、版本比较和回归门禁。

交付可挂载知识库、持久化工作区与运行结果，明确模型、Agent/Harness、裁判、生成器和模拟用户的角色。教材、代码、数据、报告、Docker命令及GitHub/飞书入口齐全且验证后，才视为全套课程完成。数字用于解释原理；构造演示、回放、历史运行与本次实测分别标注。
