# 课程目标与制作规范

这套课用于教学：通过一个可运行的编程 Agent，学会怎样设计评测、解释结果、定位问题，并读懂 DeepEval 与 Ragas 背后的关键原理。读者会 Python，了解 RAG 和 Agent。

## 课程怎样递进

[16课大纲](curriculum.md)是内容范围的依据。第1—4课建立成功条件、样本、数据和评分；第5—10课沿 TinyRAG 讲上下文与答案；第11—13课讲工具、任务和会话；第14—16课完成裁判校准、版本比较与回归。

每课只有一个核心问题。需要新的 Agent 能力时，只加入本课必需的部分；讲评分方法时，直接复用已有 Agent。代码少，靠实际输入、关键分支和输出把原理讲透。

第1课保留模型请求、Bash、消息回填和独立评分。第2课再引入具名工具、必要权限和统一样本。第5课才接知识库。完整 Agent 在最后组合，不提前贴入各课。

## 教材怎样写

参考 Learn Claude Code 的实际中文课文：从具体困难出发，给出解决机制，再沿代码解释工作原理，最后留几个可以动手观察的问题。章节服务于知识点，不规定每课必须六节或六步。

主文只放关键片段。完整源码保持可执行，片段与函数行为一致。第一次出现概念时，用当前任务说明它的作用；例如先看文件没有生成，再解释为什么模型停止不能代表任务完成。

源码导读继续追到 DeepEval、Ragas 的输入校验、判据、模型裁决、聚合和边界。当前课没有原生 SDK 调用时，明确说明只借鉴了组织方式。用固定提交链接核对实现，官方文档解释概念，不混写两套框架的同名指标。

练习给具体改动和观察问题，参考解解释因果。需要图时只解释关键结构，不堆架构全景。语言直接、简洁，读者能沿着代码理解每一步为何存在。

首页和教材正文不放制作过程、成绩列表、验收报告或教材服务启动说明。运行证据保存在单独文件中。构造样本、手算数字与真实运行分别标明，不能用编造数字替代实测。

## 怎样制作与核对

1. 先锁定本课问题、输入和成功条件，核对前课依赖及两套框架的实际源码。
2. 完成最小场景和评分代码，把失败、停止、拒绝、零分与未定义分开。
3. 用 PocketFlow-Tutorial-Codebase-Knowledge 读取本课代码，生成教材草稿；人工核对代码与解释，按上述讲法改写和润色。
4. 在 Docker 中执行模型驱动的任务，再独立评分；用明确标记的构造反例检查评分器会拒绝“只说完成”。必要的软件检查放在教材之外。
5. 检查教材片段、练习答案、代码入口、来源链接和知识库挂载是否对应。
6. 发布 GitHub，更新既有飞书云文档，再读取远端确认内容。生成凭证及运行记录不混入教学主线。
