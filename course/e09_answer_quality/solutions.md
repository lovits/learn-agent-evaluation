# e09 参考解释

[练习](exercises.md) · [教材](README.zh.md)

1. 对 `incomplete`，TP=1、FP=0、FN=2，精确率为 `1`，召回率为 `1/3`，F1 为 `1/2`。调大 `beta` 到 `2.0` 会放大 FN 的权重，分数降至 `5/13`（约 `0.385`）；调小 `beta` 到 `0.5` 会减弱遗漏惩罚，分数升至 `5/7`（约 `0.714`）。整个过程中事实 ID 集合和 TP/FP/FN 计数保持不变。
2. 不能直接判定造假。FP 只说明该陈述没有出现在当前题目定义的参考集合中，可能只是答非所问的真实信息。若参考集合自身漏掉了正当要点，对应陈述也会被计为 FP，因此在根据 FP 下结论前，要先复核题目范围、参考清单完整度与文档版本。
3. 两者的 `retrieval_context` 不同。`complete` 实际拿到了 `atlas/release.md` 和 `atlas/logs.md`，结论有证据支撑；`unsupported_answer` 只拿到了 `atlas/logs.md`，却在缺乏发布规范的条件下自信输出全部要求，违反了 `task_metric` 中的证据边界要求。
4. 拒答是否合理取决于当时可见的 `retrieval_context`。当上下文已经包含完整的发布规范时，依然回复“资料不足、无法确认”属于未利用现有证据，`task_metric` 的 `Rubric` 明确将该行为判为 `0` 分。
5. 这两句话共享绝大多数关键词和句式，“通过”与“失败”一词之差却把发布条件彻底反转。字面相似度只捕捉词面接近度，`AnswerRelevancyMetric` 也只看陈述是否围绕发布问题展开，两者都不校验条件正误；核对正误仍需要对照参考事实或基于上下文与参考的语义裁决。
6. 需要补充对照 `expected_output` 的事实覆盖检查（如 `fact_scores` 中的召回率与 FN）以及核对证据边界的 `task_metric`。`AnswerRelevancyMetric` 的分母只包含回答已经抽出的 `statements`，用户问到但模型漏答的要点不会进入分母，因此切题性高不等于答全或答对。
