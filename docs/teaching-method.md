# Learn Claude Code 的学习方式与本课程的改编规则

被评测对象是已固定版本的 Learn Claude Code 编程 Agent。课程参考其当前 s01–s17 主线，
以源码和每课 README 为依据，不把官方 Claude Code 产品的全部功能视为本仓库已有实现。

## 原项目怎样教

原项目先提出一个具体困难，再增加解决这个困难的最小机制。s01 用 agent_loop 与 bash
建立“模型决定、工具执行、结果返回模型”的循环；s02 保留循环，把执行位置替换成
工具名到 handler 的分发表，加入 read/write/edit/glob。每课给出工作原理、关键片段、
可运行 code.py、试验任务、相对上一课的变化和下一课的问题。

其递进主线为：循环 → 工具 → 权限 → hooks → 计划 → 子任务 → skills → 上下文压缩
→ 记忆 → 任务图 → 后台任务 → 调度 → 团队 → MCP → 集成 → workflow 续跑 → 目标闭环。
读者每次只需要理解一个新的机制，后面的能力通过已介绍的基础逐步接入。

## 怎样改成评测课

每课按照：问题 → 要评测什么 → Agent 的最小代码增量 → 数据与评分标准 →
运行实验 → 解释分数与失败 → 指标源码 → 练习验收 → 下一课。

正文只展示解释当前问题必需的代码，通常按功能拆成短片段；完整运行代码放在本课 code.py。
必要的共享模块必须已经在前课介绍，并列清依赖；禁止先导入一个包含全部机制的集成 Agent
再声称本课只是最小循环。第1课仅运行循环与 bash，集成视图到结课才进入。

所谓简化，是整理重复实现、启动方式和讲解顺序。工具接口、权限、状态和停止条件等
功能契约以固定上游源码为基准。完整能力保留清单见生成输入 agent-capabilities.json；
17项机制均有引入或评测的课程归属。清单目前是实现计划，不等于功能已迁移并验证。

## 一课的完整交付

- README.zh.md：问题、目标、知识、关键代码、实验解释和来源。
- code.py：能独立启动本课场景，只依赖已介绍的共享模块。
- eval.py：执行本课评分并保存逐样本结果。
- cases.jsonl：问题、证据、预期结果、来源、数据划分与审核状态。
- exercises.md / solutions.md：动手题、参考解与可观察验收条件。
- 示例报告：注明预设回放或真实运行，保存版本、参数、错误、跳过和成本。

这些是后续制作规范，本轮不将这些计划文件描述为已经全部生成。

源码阅读按输入校验 → prompt/schema → 模型调用 → verdict → 聚合 → 结果对象进行。
同名指标分别解释，确定性文件/测试断言与模型推断的完成度分别报告。

## 统一正文写法与落实进度

采用Learn Claude Code实际正文的带读方式：问题、解决方案、工作原理、相对前课变更、试一下、接下来。工作原理将一次机制变化拆成短步骤，每步先说明遇到什么问题，再解释一段真实代码，交代输入、输出和接入位置。主文不以指标清单、测试数字或完成报告为主线；详细源码、实验记录和验收放附页。

第7课的[逐项对应与上游阅读记录](../references/e07-teaching-pattern.md)列出实际参考的章节、代码段与正文标准。第1课现已按同一标准重写，补入最小循环和独立验收两张结构图，详见[改写计划](../references/e01-rewrite-plan.md)。第2、3课已按同样的六部分正文与六步代码完成重写和审校；第4至6课尚待重写，第7课继续纳入统一复核。见[整套制作计划](course-production-plan.md)与[正文标准](../references/textbook-writing-standard.md)。
