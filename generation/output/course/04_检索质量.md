## 答案分散在两份文档里

Agent 要为 `POST /upload` 编写接入说明。`auth.md` 写认证头，`limits.md` 写最大1048576字节及超限状态413。

只拿到认证文档，返回内容完全切题，却仍答不出后两项。本课接入 Datawhale TinyRAG，让已有 Agent 通过 `search_knowledge` 读取挂载知识库，再分别评价相关、覆盖与排序。

## TinyRAG 只有几块

```text
只读文档 → 切成片段 → 文本向量 → VectorStore
                                      ↑
问题 → 查询向量 → 余弦相似度 → top-k 片段 → Agent
```

TinyRAG 的核心在于把文档与查询放到相同向量空间。`VectorStore` 保存向量，用余弦相似度排序，再返回最接近的片段。

本课嵌入接口使用本地 TF-IDF：按语料中的词项及稀有程度形成向量，无需模型密钥。它是词法向量基线，不具备神经嵌入的同义理解；更换嵌入实现时，向量库的查询接口仍可复用。

## 从挂载文件到片段

[`catalog`](https://github.com/lovits/learn-agent-evaluation/blob/main/eval_course/knowledge.py) 读取只读挂载里的 Markdown 和文本。适配层按字符窗口分块，保留原文、起止位置和来源：

```python
text = doc["text"][start : start + size]
```

每个片段有 `chunk_id`、片段哈希和 `source_sha256`。同一文档可以产生多个片段，评价片段覆盖和评价文档覆盖时，要使用不同的 ID 单位。

课程窗口为1200字符、重叠150字符。短规范只有一个片段；长文档相邻窗口保留重叠。这里明确按字符计量，源码导读会对照上游分块方法。

## 建向量，再按问题查询

[`retrieve`](https://github.com/lovits/learn-agent-evaluation/blob/main/eval_course/tinyrag.py) 把片段交给实际 TinyRAG `VectorStore`：

```python
embedding = CorpusEmbeddings(list(entries))
store = VectorStore(list(entries))
store.get_vector(embedding)
ranked = store.query(query, embedding, k=min(limit, len(entries)))
```

`get_vector` 对片段编码；`query` 对问题编码，再与已存向量比较。返回值映射回来源字段，并过滤没有向量重合的零相似度结果。

为了让课程数据保持透明，这个小语料在查询时重建内存索引，更换挂载即可读取新内容。TinyRAG 也提供持久化接口，使用它时还要检查索引与文档、分块和嵌入版本是否一致。

## Agent 循环只接一个新工具

[`dispatch`](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e04_retrieval/code.py) 截获 `search_knowledge`，其他动作继续交给前课。检索结果作为普通工具结果回填，Agent 再据此写接入说明。

相似度是召回排序依据。它并不直接知道本题必须包含认证头、字节上限和状态码，不能当成业务正确率。

## 相关与找全分别计算

标注相关文档为 `{auth, limits}`，手算几种返回：

| 返回 | 文档精度 | 文档召回 |
|---|---:|---:|
| `[auth]` | 1 | 1/2 |
| `[auth, limits]` | 1 | 1 |
| `[auth, limits, noise]` | 2/3 | 1 |

精度的分母是返回数，召回的分母是应找回的相关总数。`ranking` 在文档级先按来源 ID 去重；若要评价长文片段，应改用 `chunk_id` 并准备相应标注。

## 排序还改变什么

`[auth, limits, noise]` 与 `[noise, auth, limits]` 的精度和召回相同，相关位置的平均精度却分别为1与 `(1/2 + 2/3)/2 = 7/12`。

`ap_retrieved` 除以本次相关命中数，`ap_reference` 除以全部标注相关数。MRR 只看首个相关位置，NDCG 给靠后位置打折。

DeepEval 与 Ragas 的 Context Precision 让模型判断片段是否支持回答，再按顺序聚合；Context Recall 检查参考声明被支持的比例。DeepEval Contextual Relevancy 则检查上下文声明是否切题。

认证、限额和413若拆成三条声明，只找到认证时，声明召回可能为1/3，而文档召回是1/2。先辨认单位，再解释分数。

# e04 源码导读：TinyRAG 的排序怎样进入评测

[教材](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e04_retrieval/README.zh.md) · [挂载读取](https://github.com/lovits/learn-agent-evaluation/blob/main/eval_course/knowledge.py) · [检索适配](https://github.com/lovits/learn-agent-evaluation/blob/main/eval_course/tinyrag.py) · [评分](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e04_retrieval/eval.py)

## 先沿 TinyRAG 走一遍

[上游 TinyRAG](https://github.com/datawhalechina/tiny-universe/tree/a5ae08d56bbefb20b1cf56fa34ed5a3157cdd2c2/content/TinyRAG) 将流程拆成读取、分块、嵌入、向量库与生成。本课保留实际 `VectorStore` 算法，生成继续交给已有 Agent 与模型入口。

```text
catalog → chunks → CorpusEmbeddings
                         ↓
               VectorStore.get_vector
                         ↓
       VectorStore.query → 来源映射 → search_knowledge
```

## query 只做三件事

[VectorBase.py](https://github.com/lovits/learn-agent-evaluation/blob/main/vendor/tinyrag/VectorBase.py) 的原生主干是：

```python
query_vector = EmbeddingModel.get_embedding(query)
result = np.array([self.get_similarity(query_vector, vector)
                   for vector in self.vectors])
return np.array(self.document)[result.argsort()[-k:][::-1]].tolist()
```

余弦比较方向，分数高的先返回。相同内容可能来自不同文档，适配层给索引条目附来源前缀，返回后映射回片段及来源哈希。

`BaseEmbeddings.cosine_similarity` 使用点积除以范数乘积，零向量返回0。课程裁掉供应商导入及修改环境变量的副作用，保留计算；来源与许可见 [TinyRAG 说明](https://github.com/lovits/learn-agent-evaluation/blob/main/vendor/tinyrag/LICENSE.md)。

## 嵌入与分块有哪些适配

`CorpusEmbeddings` 在当前语料上拟合 TF-IDF，再提供 `get_embedding`。词项沿用英文单词与中文相邻双字。这是无密钥词法向量，不把它解释成预训练语义模型。

`chunks` 按字符窗口保留空白和原文偏移。上游 `ReadFiles.get_chunk` 同时使用 token 长度与字符切片，并会去空格；本课改用明确的字符单位，避免把代码空白或长行丢掉。[上游工具副本](https://github.com/lovits/learn-agent-evaluation/blob/main/vendor/tinyrag/upstream/utils.py.txt)用于对照，不作为本课读取入口。

`sha256` 标识当前片段，`source_sha256` 标识原文件。`matches` 仅保留词项交集计数供旧调用者读取，排序由 `similarity` 决定。换文档后重建当前小型索引，不复用旧向量。

## 文档与片段是两种标注

`ranking` 先按传入 ID 去重。文档级用来源路径，片段级用 `chunk_id`；标注集合必须采用相同单位。

precision 分母为返回 ID 数，recall 分母为标注相关总数；AP 累计相关位置的 `P@i`，再按 retrieved 或 reference 口径归一化。MRR 是首相关排名倒数；二元 NDCG 用 `1/log2(rank+1)` 折扣。

已知标注非空而返回为空时规则记0；标注本身为空则无法定义召回。

## DeepEval 的判定对象

[Contextual Precision 文档](https://deepeval.com/docs/metrics-contextual-precision) · [实现](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/metrics/contextual_precision/contextual_precision.py)

`prepare_measure` 检查问题、expected_output 与 retrieval_context；`_generate_verdicts` 逐片段给有用性判断；`_calculate_score` 对相关位置累计精度，再除以本次相关数。

[Contextual Recall 文档](https://deepeval.com/docs/metrics-contextual-recall) · [实现](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/metrics/contextual_recall/contextual_recall.py)按参考声明是否能归因到片段计算 yes 比例。它的分母是声明数。

[Contextual Relevancy](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/metrics/contextual_relevancy/contextual_relevancy.py) 不需要参考，按上下文声明是否与问题相关聚合。嵌套 `verdicts_list` 展平后计数，长片段可能贡献更多声明。

## Ragas 的参考口径

[Context Precision 文档](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/) · [实现](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/metrics/collections/context_precision/metric.py)

WithReference 逐片段判断问题、reference 与 context 的支持关系，再计算平均精度。WithoutReference 用回答替换 reference，回答自己的遗漏也可能掩盖检索缺口。

[Context Recall 文档](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/) · [实现](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/metrics/collections/context_recall/metric.py)合并上下文，按参考声明的 attributed 比例评分；无 classifications 可返回 NaN，必要输入为空则更早报错。

现代 collections 使用 `InstructorBaseRagasLLM`，与旧接口分开适配。模型分数、未定义和请求错误分别记录；相似度只影响召回，不能代替这些质量判断。
