# e01: 定义成功

[课程](https://github.com/lovits/learn-agent-evaluation/blob/main/README.md) · **e01** → [e02 保存一次运行](https://github.com/lovits/learn-agent-evaluation/blob/main/docs/curriculum.md#02-保存一次运行)

> 模型停止了，还要看它留下了什么。

## 问题

让 Agent 创建 `hello.py`，文件里只有一条 `print("Hello, World!")`，然后运行它。

模型回答“已经完成”。你打开目录，文件却不存在。

这里有两个问题。首先，模型需要工具才能真正操作文件。其次，即使模型调用过工具，我们仍要判断结果是否满足任务。一次模型回复，把这两件事都遮住了。

本课先接上最小执行循环，再给它一个独立的评分器。

## 解决方案

模型提出动作，执行框架运行 Bash，把真实结果交回模型。这个负责调用、执行和回填的框架，就是 Harness。

![模型与 Bash 之间的循环](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e01_agent_baseline/images/agent-loop.png?raw=true)

循环结束后，评分器读取实际文件和工具记录，按任务条件判断是否完成。

![运行与独立评分的代码关系](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e01_agent_baseline/images/evaluation-path.png?raw=true)

模型负责选择下一步。循环负责让动作发生。评分器负责判断发生的事是否符合要求。

## 工作原理

### 1. 从任务开始

[code.py](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e01_agent_baseline/code.py) 的 `agent_loop` 先建立消息列表：

```python
messages = [{"role": "user", "content": task}]
```

`messages` 是模型接下来会看到的内容。最初只有任务；执行过工具以后，里面会有真实结果。

模型通过 `model(messages)` 返回下一步。这里用一个小 JSON 结构表示动作：

```json
{
  "tool_calls": [{"command": "python3 hello.py"}],
  "answer": ""
}
```

模型接口只生成动作，命令由 Docker 里的课程 Agent 执行。Learn Claude Code 原版使用 `tool_use` / `tool_result`；本课用 JSON 适配本机已登录的模型，循环的职责相同。

### 2. 没有动作，就停下

收到响应以后，先把它加入历史，再看是否还有工具调用。下面是函数中的关键分支：

```python
reply = response["reply"]
messages.append({"role": "assistant", "content": reply})
if not reply["tool_calls"]:
    run.update(status="finished", final_answer=reply["answer"])
    break
```

`finished` 只表示模型结束了本次工作。模型第一轮就说“完成”，也会走到这里。这个状态还没有检查文件。

`run` 的初始状态设为 `step_limit`。只有模型正常停止，才改为 `finished`；循环用完步数时保留原状态，模型调用失败则改为 `model_error`。这样，每一种结束方式都有明确含义。

### 3. 执行动作，保留结果

有动作时，就逐条交给 Bash。循环中的执行与回填部分是：

```python
results = []
for index, call in enumerate(reply["tool_calls"]):
    result = run_bash(call["command"], workspace, timeout=tool_timeout)
    # 完整函数在这里把命令和 result 加入 events。
    results.append(result)
messages.append({"role": "tool", "content": results})
```

`run_bash` 在本次练习目录中执行命令，返回 `stdout`、`stderr`、`exit_code` 和执行状态。下一轮模型能看到真实输出或报错，再决定继续、修正或停止。

`messages` 用于继续工作，`events` 保存实际发生的过程。评分器读 `events`，不会把回答里的“我运行过了”转换成一条执行记录。

每次任务从新目录开始，避免上次留下的 `hello.py` 混进本次结果。模型连接、进程超时和目录准备放在 [runtime.py](https://github.com/lovits/learn-agent-evaluation/blob/main/eval_course/runtime.py)，核心循环保留在本课。先看清循环，再按需要读这些细节。

### 4. 从真实结果判断完成

现在转到 [eval.py](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e01_agent_baseline/eval.py)。它读取运行记录与工作目录，先检查循环是否结束、是否执行过 Bash，再检查当前任务的规则：

```python
tools = [e for e in report["events"] if e["type"] == "bash"]
checks = [
    {"name": "model_stopped", "passed": report["status"] == "finished"},
    {"name": "bash_was_executed", "passed": bool(tools)},
]
for rule in criteria["checks"]:
    checks.append({"name": rule["name"], "passed": check_rule(rule, tools, workspace)})
```

`create_and_run` 要求两类证据：成功命令的输出包含 `Hello, World!`，以及实际 `hello.py` 的语法树符合指定的单条 `print`。

语法树检查接受引号、注释和普通空白变化。它只检查这个小任务的代码结构，不能证明任意两个程序功能等价。输出包含指定文字，也不能单独证明所有行为正确。因此评分器把几条条件放在一起，按当前任务解释。

### 5. 把评分和解释留下来

汇总取决于两个判断，下面省略了返回值中的标识字段：

```python
return {
    # 省略运行标识与说明字段。
    "passed": all(c["passed"] for c in checks),
    "score": sum(c["passed"] for c in checks) / len(checks),
    "checks": checks,
}
```

对应返回值保存在 `evaluate` 的结果中。`score` 是本次规则的通过比例，方便找到缺项；只有全部条件满足，`passed` 才为真。这不是“Agent 能力的百分比”。

只回复“完成”、没有动作也没有文件的记录，可以是 `finished`，评分仍会失败。

再看一个相反的例子：`command_error` 的任务是运行原脚本并观察错误。脚本非零退出，正好提供了任务要求的证据。工具是否成功和任务是否完成，要根据用户目标分别判断。

## 变更内容

| 部分 | 作用 |
|---|---|
| `agent_loop` | 请求模型，执行动作，回填结果，直到停止 |
| `run_bash` | 让动作发生，并保留输出、错误和退出码 |
| 新练习目录 | 保存本次任务的初始文件与产物 |
| `evaluate` / `check_rule` | 按任务规则读取实际证据，给出逐项判断 |

本课使用自己的规则评分器。DeepEval、Ragas 对任务、运行和评价的分工见[源码导读](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e01_agent_baseline/source_walkthrough.md)；原生样本接口从下一课开始接入。

# e01 源码导读：成功条件写在哪里

[教材](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e01_agent_baseline/README.zh.md) · [循环](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e01_agent_baseline/code.py) · [评分器](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e01_agent_baseline/eval.py)

## 先找两个入口

`code.py:main` 读公开任务，创建新目录，调用 `agent_loop`，保存运行报告。`eval.py:main` 读这份报告与任务规则，调用 `evaluate`，保存逐项判断。

两者之间传的是实际运行结果。`evaluate` 不调用模型，也不运行 Agent 生成的程序；它读执行事件和文件。Docker 中评分进程的工作目录挂载只读，评分标准不挂给 Agent。

| 位置 | 顺着什么读 |
|---|---|
| [code.py](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e01_agent_baseline/code.py) | `load_cases → main → agent_loop` |
| [runtime.py](https://github.com/lovits/learn-agent-evaluation/blob/main/eval_course/runtime.py) | `call_model`、`run_bash`、`prepare_workspace` |
| [eval.py](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e01_agent_baseline/eval.py) | `main → evaluate → check_rule` |
| [run_e01.py](https://github.com/lovits/learn-agent-evaluation/blob/main/tools/run_e01.py) | 先执行任务，再启动独立评分容器 |

`runtime.py` 收拢了传输和进程细节，供各课复用。原有导入入口仍可用；本课核心是 `agent_loop` 的请求、执行、回填和停止。

## 循环里的数据

`messages` 是模型可见历史。`events` 是运行记录，保留模型响应与 Bash 的命令和结果。只有执行框架写入的 Bash 事件，才能提供本课需要的动作证据。

`call_model` 调用宿主模型接口，检查返回的 `answer`、`tool_calls` 和命令结构。本机 Codex 只提供结构化响应，其自身工具关闭；实际命令由课程容器执行。

`run_bash` 保留输出、退出码、超时状态与截断标记。工具报错也回填模型。`prepare_workspace` 创建新目录、写入初始文件，拒绝越出该目录的初始路径。

独立目录防止旧文件混入；进程工作目录和教学阻断词表不是完整的 Bash 权限边界。这里不把教学执行器当成通用安全隔离方案。

## 评分器读哪些证据

`evaluate` 先检查正常停止和实际 Bash 事件，再按 `criteria["checks"]` 调用 `check_rule`。

| 规则 | 证据 | 能说明什么 |
|---|---|---|
| `successful_stdout_contains` | 退出码为0的对应 stdout | 某次成功命令输出了指定文字 |
| `error_contains` | 非零退出的 stderr | 某次命令确实返回了指定错误 |
| `python_ast` | 实际文件的 AST | 文件满足当前指定结构 |
| `file_sha256` | 实际文件内容哈希 | 指定文件内容保持一致 |

`python_ast` 解析文件与参考代码，比较 `ast.dump`。读取前会确认路径位于当前目录内。语法错误或无法解码不会通过。AST 相同不等于通用行为正确；stdout 命中也不保证某个特定命令来源。因此本课规则用于演示任务合同，不声称能抵抗任意投机。

汇总中 `score = 通过项数 / 全部项数`，`passed = all(逐项判断)`。规则权重相同，诊断比例依赖你写了多少条规则，跨任务不能直接当作可比的能力分。

## 对照 Learn Claude Code

固定版本的 [s01 agent_loop](https://github.com/shareAI-lab/learn-claude-code/blob/448c75bb596917ad196cc1fb7558f459c5c50fdd/s01_agent_loop/code.py) 在没有 `tool_use` 时返回；有调用就执行 Bash，把 `tool_result` 放回消息。

本课沿用这个循环。JSON 动作适配不同模型入口，增加步数上限和必要记录，再把任务评分放到循环之外。运行状态描述执行停在哪里，任务规则描述结果是否满足要求。

## DeepEval：预期、实际运行与指标

先看 [Golden](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/dataset/golden.py) 和 [LLMTestCase](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/test_case/llm_test_case.py)。前者保存输入与预期，后者携带待评分的实际输出及相关字段。预期结果不能填成“实际运行已经做到”。

再读 [evaluate](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/evaluate/evaluate.py)：

1. `validate_evaluate_inputs` 校验样本与评分配置。
2. 根据配置进入同步或异步执行分支，将样本交给指标。
3. 汇集逐样本结果。选择什么指标，才决定怎样定义“好”。

对照[官方评测入门](https://deepeval.com/docs/evaluation-introduction)，本课任务、报告和规则分别承担预期、实际记录和评分标准的职责。文件规则是本课自己的实现，没有调用 DeepEval 原生指标。

## Ragas：一行任务怎样得到结果

读 [Dataset](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/dataset.py) 与 [experiment.py](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/experiment.py)。`ExperimentWrapper.arun` 为数据行调用被装饰函数，将返回结果收进 `Experiment`。

这个调度器不会替你定义“hello.py 写对了”。被装饰函数需要调用应用，并明确计算或携带评价结果。业务评分来自你选用的规则或指标。

[官方实验概念](https://docs.ragas.io/en/stable/concepts/experimentation/)解释数据集、实验函数和评价的关系；[指标概览](https://docs.ragas.io/en/stable/concepts/metrics/overview/)解释端到端与组件评价。本课同样先运行、后评价，尚未调用 Ragas 原生指标。

下一课才把运行记录转换成两框架的实际样本类型。本课先把一个前提立住：评分需要独立、可追溯的实际输入。
