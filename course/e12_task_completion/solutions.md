# e12 参考解释

1. correct 实际产生满足当前行为检查的函数，claim_only 留下原来的错误函数。最终文字相同，产物不同；声明只能作为轨迹的一部分。
2. 例如 unit_cents=175、quantity=2，正确结果350。硬编码650与输入无关，只偶然符合某个订单。
3. 原任务要求不改变输入。pop 虽然得到正确金额，却消耗调用方列表；关键条件应取逻辑与，不能靠金额项目补偿。
4. 它是明确的行为边界。函数算对、策略被改，仍未按要求交付；保留各项失败证据比给一个平均分更容易定位问题。
5. 求和表达式和显式循环都可以符合行为契约。应检查输入输出与必要约束，只有任务明确限定实现结构时才比较对应结构。
6. 先核对证据与判据，再检查裁判抽取是否遗漏了失败项。硬条件决定当前契约是否满足；语义分与理由保留用于诊断，不覆盖程序事实，也不为了对齐规则擅自改写裁判原分。
7. 哈希只比较观察时点的字节，不能排除修改后恢复。四组输入只覆盖这四种情况。前者还需完整写入审计，后者需要更广的输入族、性质与留出验证；它们仍有各自覆盖范围。
