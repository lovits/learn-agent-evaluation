# 第16课样本与评测记录

## 样本与证据范围

[cases.jsonl](cases.jsonl) 包含三个公开构造的 Atlas billing 回归任务：漏乘数量、空订单错误、已有正确实现。初始文件、参考与知识库文档哈希固定；每题两个版本分别使用新工作区，唯一 Agent 提示变化是更明确的最终说明要求。它们同属一个题族，不是独立留出基准。

[failure_origin.json](failure_origin.json) 保留第12课受控反例与真实裁判原分0.95，程序契约为1；动作与“已完成”回答是构造的，不能称为自主模型失败。

[observed_failure.json](observed_failure.json) 则来自本课真实模型运行：文件已修复，但模型在最终回复前遇到502，没有最终答案；旧任务完成指标仍概括出“已说明”。运行与可用性检查使接受状态保持未知，旧 gate 为 blocked。它说明为何不能只靠单项语义分决定任务完成。

## 实验分开记录

初次 TaskCompletion 综合实验记录为 e16-suite-3260708bc9814150bda2de104e7930c6：三个分项扣分理由遗漏了真实工具过程，另有未要求的仓库级检查被额外扣分；其中一次模型接口502。原始判分、失败和工具记录全部保留。

后续改用显式 G-Eval 量表，直接提供原始回答、独立观察与工具事件，分别给两个版本使用同一套判据。没有覆盖原回答或旧分，也没有用重试替换一个已知业务低分。

默认离线运行中的语义分为构造 fixture，只验证组合流程。原生受控评分和真实模型执行的最终记录、调用数、分项结果与可用性见 assessment.json；真实模型接口异常单列，恢复尝试单独保留来源。

## 当前结果

| 运行 | 实际结果 |
|---|---|
| 最终离线受控流程 | 真实文件效果与构造语义分分开保存，gate 在构造范围接受 |
| 受控动作＋原生裁判 | 12次真实 DeepEval 请求；三个“已完成”反例均为0，完整说明均为1，资料召回均为1 |
| 真实模型＋显式量表 | 基线3/3完成并通过；候选1/3完成通过，另2条发生接口错误，整体 blocked |
| 仅恢复两条接口失败 | 两条仍因无效工具参数报错，保留未知；没有覆盖原记录或接受提示改动 |

真实模型原轮共有23次桥接请求尝试，收到21条成功响应；其中候选两条未收到有效下一步。原轮语义评分12次，恢复评分4次，均不混入 Agent 请求数。恢复行是独立新工作区，不把已知业务低分反复重跑到满意为止。

空订单基线途中有两次 Bash 检查报错，之后观察错误并恢复，最终独立行为通过。这说明中途工具错误与最终交付失败要分别判断。

这次提示改动没有获得接受。项目完成的是可运行的评测与阻止错误接受的流程，不是对某个提示词必然更好的证明。

## 结果怎样解释

行为检查由评测程序重新加载文件执行；金额、空订单、零数量、输入保持和 policy.txt 均有独立观察。实际工具轨迹用于核对知识查询和读取实现，语义判断只依据明确任务要求，不能添加隐藏验收条件。

候选任一确定关键失败即拒绝；任一必要观察或评分未知则未决。两侧都通过只报告 no_regression_observed，不宣称新增提示词提升质量。

## 软件与发布核对

Docker 的知识库为只读绑定，记录与练习目录可写。全仓库检查、独立行为回归和 reader 页面核对均由制作者执行；最终数量记录于 assessment.json。初次新增软件检查中发现测试索引写错一层，已修正后重跑，没有改评分结果来迎合检查。

模型默认选择方式有记录，但接口未报告固定快照；未知价格保持空值。小型公开回归和已恢复运行的条件性结果，不能作为生产可用性或广泛能力证明。
