# 编程 Agent 评测课程的制作计划

本轮交付课程设计、知识地图、16课逐课要求和PocketFlow生成凭证。
第1、2课代码已制作并通过真实Docker实验；旧Faithfulness样章已清理。后续逐课递进，详细制作要求见course-specification.md。

## 设计基准

学习对象是固定版本Learn Claude Code仓库的编程Agent。课数由24合并为16，原知识文字逐项保留。
每课按评测需求加入上游机制，保持已经介绍的能力。对照17课能力清单核对工具接口、
权限、状态、调度和停止等契约，逐步集成，到结课再审查完整覆盖。功能保留目前是验收约束。
模型决策存在差异时，依据可接受结果和约束验收，不要求每次生成相同文字或唯一轨迹。

| 阶段 | 工作与产物 | 通过条件与当前状态 |
|---|---|---|
| 1. 材料与边界 | 核对原项目教学法、两框架评测/数据能力、固定版本 | 本轮完成；保留源码与文档依据，不将动态缺失或未执行示例当实测 |
| 2. 逐课拆包 | 16课要求、24→16知识映射、17机制归属、源码/文档索引 | 本轮完成结构核验；每个旧课恰好归入一课，每个机制有归属，引用路径存在 |
| 3. PocketFlow规划 | 原版FetchRepo、IdentifyAbstractions、AnalyzeRelationships、OrderChapters，加课程设计写作节点 | 本轮运行，记录实际模型调用、节点和输入输出哈希；只生成计划 |
| 4. 第1–2课与第5课试做 | 最小循环、工具/权限/事件；制作编程版Faithfulness案例并接入真实Agent输出 | 后续；一课一个可运行入口，正文不贴集成Agent；三个试做课验证代码/教材组织 |
| 5. 第3–9课 | 判分方法、知识库RAG、数据生成、故障诊断与版本实验 | 后续；手算/规则/SDK结果可追溯；候选数据审核；分层和留出数据分离 |
| 6. 第10–14课 | 工具/MCP、真实完成、多轮记忆、计划协作、后台调度与效率 | 后续；状态验收独立于Agent说法；各机制有正常、失败、边界任务 |
| 7. 第15–16课 | 校准、回归、工作流续跑、源码完整链、结课报告 | 后续；回归故障被门禁发现；17机制逐项检查；完成基线/改进/限制说明 |
| 8. 教材发布 | 每课验证后将白名单代码、结果和依据交给PocketFlow写作节点，再审校 | 后续；实际命令复核、来源可访问、片段与完整程序一致，更新GitHub与Docker阅读器 |

## 逐课目录规范

```text
lessons/e01_agent_baseline/
  README.zh.md       # 知识与关键代码、与前课差异
  code.py            # 本课可运行Agent入口
  eval.py            # 本课评分入口
  cases.jsonl        # 样本、来源、预期、审核状态
  exercises.md
  solutions.md
  example_report.json
```

这是一份待实现的结构。共享代码仅承载前课已经介绍的机制；每课列明已启用功能与新增片段，
避免一个共享大文件提前隐藏整套Agent。源码片段给出上游文件、符号、commit与改编说明。
后续按课准备材料包，不把整个Agent、全套文档和所有结果一次性交给每一课。

## 运行环境与证据

Docker只读挂载knowledge_base，包含项目说明、API、架构和开发规范；每次任务使用独立可写
workspace，保存修改前后文件、diff、命令输出和退出码。runs持久化轨迹、评分、配置和成本。
评分用保留测试、reference与答案独立存放，避免进入被测Agent的知识库或普通工作目录。

教材生成已获准使用本机Codex登录。被测Agent模型、裁判、数据生成器与模拟用户分别配置；
生成教材的登录状态不等于这些运行接口均已配好。模型接口在试做阶段实际接通并验证。
无密钥的预设回放用于学习评分管线，真实模式用于评价模型和Agent；模式必须写入报告。

## 验收规则

每课至少有正常、错误与边界场景，并保留可执行代码、命令和逐样本证据。评分器用固定
合同样本验证聚合；真实Agent任务用独立文件状态和保留测试核实结果。失败、跳过、
未评分和超时单独记录，不改成0或用总体平均掩盖。原版与改编版在相同可接受任务合同下比较。

已有回放通过不等于这16课已通过。本轮只更新课程设计与生成工具，不提前承诺全部运行成绩。
