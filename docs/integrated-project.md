# 完整项目：给编程 Agent 留下一条可核对的评测链

项目入口是[第16课](../course/e16_regression/README.zh.md)及其 [code.py](../course/e16_regression/code.py)。完整项目由课程中已经出现的模块组成；每个模块仍可以回到对应课程单独阅读。

## Agent 怎样工作

用户提出修复任务，模型选择具名工具。文件工具在工作区内读写，Bash 执行必要命令，search_knowledge 调用只读挂载的 TinyRAG。工具结果进入 messages，模型继续决定动作，直到给出最终回答或达到运行边界。

第16课不固定模型首步，查询、读取、写入与检查均由实际模型决定；默认离线模式才使用明确标注的受控动作。模型传输层仅生成动作结构，实际执行归课程 Harness。

## 评测怎样工作

| 阶段 | 保留什么 | 判断依据 | 对应课程 |
|---|---|---|---|
| 定义成功 | 任务、参考、业务条件 | 明确要交付的结果 | 1 |
| 保存运行 | 输入、回答、动作、返回、产物 | 实际运行及 DeepEval 样本 | 2 |
| 准备数据 | 来源、审核、去重、题族和划分 | 参考独立于实际答案 | 3 |
| 选择评分 | 规则、量表、阈值、错误状态 | 能规则判断的先直接检查 | 4 |
| 接入知识 | 文档哈希、分块、候选、最终上下文 | TinyRAG 实际返回与送入的片段 | 5 |
| 检索与上下文 | 相关性、排序、事实覆盖 | 精度、排序、召回各有分母 | 6—7 |
| 评价回答 | 声明、证据、正确与完整 | 忠实度、相关性和任务标准 | 8—9 |
| 定位失败 | 分层对照与具体反例 | 资料、检索、组装、生成的边界 | 10 |
| 评价行动 | 工具名、参数、顺序和业务产物 | 调用正确不等于任务完成 | 11—12 |
| 多轮与裁判 | 当前约束、参考标签、分歧 | 原始历史与适用评分范围 | 13—14 |
| 比较与回归 | 同题结果、波动、成本和失败候选 | 固定判据与关键条件 | 15—16 |

指标按问题选择。综合账单任务组合行为检查、过程记录、显式任务量表与上下文召回；其他指标保留在对应课程，不把全部指标每次机械跑一遍。

## 一次改动怎样判断

先复核失败来源，将可重复的任务与明确判据纳入公开回归集。两个版本从相同初始文件分别执行，独立检查产物，再用相同语义标准评分。已知关键失败则拒绝，缺证据则保留未决；只有指定回归范围都满足时才接受这次改动。

CI 的离线流程验证真实文件效果、评测接线和构造语义分下的接受逻辑。真实模型与 DeepEval 语义实验由制作者在 Docker 中另行执行，原始结果存于各课 assessment。离线检查通过、真实模型通过和上线决策是三件不同的事。

失败候选先复核再入库。当前公开材料可用于学习与回归保护；判断广泛能力或选型，还需独立留出任务、更多题族和重复观察。
