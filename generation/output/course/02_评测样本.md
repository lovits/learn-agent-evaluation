## 一串 Bash 不容易评价

工作区里有 `calculate.py`：

```python
print(6 * 7)
```

任务是把它改成 `6 * 8`，运行，再把输出写到 `result.txt`。

一串 Bash 可以做完这些事。但若要评价“读了哪个文件、改了什么、哪一步被拒绝”，我们需要更明确的动作。因此加入 `read_file`、`write_file`、`edit_file` 和 `glob`，执行程序仍交给 Bash。

循环继续负责调用工具。本课关注怎样把这些动作留下来，形成后续评分器能读懂的样本。

## 工具定义先说清参数

[`TOOL_SPEC`](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e02_tools_traces/code.py) 声明每种工具需要什么：

```python
TOOL_SPEC = {
    "bash": {"command": "str"},
    "read_file": {"path": "str"},
    "write_file": {"path": "str", "content": "str"},
    "edit_file": {"path": "str", "old_text": "str", "new_text": "str"},
    "glob": {"pattern": "str"},
}
```

`validate_call` 解析参数并检查字段和类型。之后 `dispatch` 检查权限，最后才进入 `execute`。

```text
工具请求 → 参数校验 → 权限判断 → 执行 → 返回结果
```

读文件时，路径先解析再判断是否仍在工作目录内。`edit_file` 找到旧文本后只替换第一处；找不到就返回错误，不静默写入。

## 拒绝和报错发生在不同位置

| 状态 | 发生了什么 |
|---|---|
| `invalid_arguments` | 参数不符合工具定义 |
| `denied` | 权限不允许，工具没有执行 |
| `error` | 进入工具后出现异常或命令非零退出 |
| `timeout` | 执行超过时间限制 |
| `ok` | 工具按约定返回 |

少传 `path` 与读取不存在的文件，不该记成同一种错误。前者要修调用参数，后者可能需要先查文件。

权限判断还区分硬拒绝和需要批准的动作。批准回调返回允许或拒绝；`approval_required` 只是说明为什么进入批准分支。Bash 的教学规则覆盖有限，完整执行边界还依赖容器配置。

## 两次 read_file 怎样区分

同一轮可能读两个文件。工具名相同，结果却属于不同请求。运行时为模型响应和工具调用分配关联 ID：

```python
model_id = f"model-{step}"
call_id = f"{model_id}:tool-{index}"
hooks.append({"phase": "PreToolUse", "span_id": call_id})
policy, result = dispatch(call, workspace, approve)
```

随后事件一起保存：

```python
events.append({
    "type": "tool",
    "span_id": call_id,
    "parent_id": model_id,
    "call": call,
    "permission": policy,
    "result": result,
})
```

`span_id` 标识这次调用，`parent_id` 指向提出它的模型响应；`run_id` 区分整次任务。前后 hook 让我们知道动作停在哪一层。

[`trace_errors`](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e02_tools_traces/samples.py) 按请求顺序核对结果及 hook。缺结果、错归属、交换顺序都可以发现。它检查记录内部是否一致；实际文件是否正确，仍需另行读取。

## 同一份事实，两套样本

把任务输入与最终回答投影成单轮样本，把交互顺序投影成多轮样本：

| 内容 | DeepEval | Ragas |
|---|---|---|
| 用户任务 | `input` | `user_input` |
| 实际回答 | `actual_output` | `response` |
| 参考答案 | `expected_output` | `reference` |
| 检索证据 | `retrieval_context` | `retrieved_contexts` |
| 工具请求 | `ToolCall` | `AIMessage.tool_calls` |
| 多轮交互 | `ConversationalTestCase` | `MultiTurnSample` |

例如 DeepEval 的单轮构造：

```python
LLMTestCase(
    input=report["task"],
    actual_output=report["final_answer"],
    expected_output=reference,
    tools_called=list(deep_tools.values()),
    metadata=metadata,
)
```

文件读取输出属于工具结果，不能为了填字段放进检索证据。还没有参考答案时保留空值；具体指标需要哪些字段，要按它自己的要求检查。

# e02 源码导读：工具事件怎样变成样本

[教材](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e02_tools_traces/README.zh.md) · [工具与循环](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e02_tools_traces/code.py) · [样本适配](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e02_tools_traces/samples.py)

## 从 dispatch 进入

```text
validate_call → permission → execute
                              ↓
                     event + Pre/Post hook
                              ↓
                       trace_errors
                              ↓
                       native_samples
```

`execute` 按工具名分支。上游 [s02](https://github.com/shareAI-lab/learn-claude-code/blob/448c75bb596917ad196cc1fb7558f459c5c50fdd/s02_tool_use/code.py) 用 `TOOL_HANDLERS` 查表，分发职责相同；本课没有加入可选的读取行数参数。

[s03](https://github.com/shareAI-lab/learn-claude-code/blob/448c75bb596917ad196cc1fb7558f459c5c50fdd/s03_permission/code.py) 在执行前检查权限；[s04](https://github.com/shareAI-lab/learn-claude-code/blob/448c75bb596917ad196cc1fb7558f459c5c50fdd/s04_hooks/code.py) 提供 hook 接入点。本课直接记录这些位置，每个请求都有 Pre/Post 配对，包括参数错误与拒绝，便于追踪。

路径先 `resolve` 再检查边界，防止文件链接绕出工作区。Bash 保留自己的执行状态；拒绝和执行失败不能互相改写。

## 一条轨迹有三层身份

`run_id` 是整次任务；`model-N` 是一次模型响应；`model-N:tool-i` 是其中一个请求。`trace_errors` 按这些身份与原始动作核对结果顺序，同时检查 hook 覆盖。

关联正确只能证明记录自洽。若要判断操作是否达成目标，还要读取实际文件或业务状态。

## DeepEval 的嵌套类型要恢复

[样本文档](https://deepeval.com/docs/evaluation-test-cases)与 [llm_test_case.py](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/test_case/llm_test_case.py) 一起看。`ToolCall` 保存 `name`、`input_parameters` 与 `output`。固定版本的前置校验要求 `tools_called` 中已经是 `ToolCall` 实例，所以 JSON 恢复时，`restore_samples` 先恢复嵌套对象。

[ConversationalTestCase](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/test_case/conversational_test_case.py) 的 `Turn` 采用 user/assistant 角色。工具输出留在对应 assistant 的 `ToolCall.output`，不另造一个 tool 角色。

[原生 tracing](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/tracing/tracing.py) 则用 `parent_uuid` 挂接子节点，必要时修复暂时找不到父节点的 span。本课先用本地事件解释归属，原生 trace 在计划课接入。

## Ragas 的多轮样本保留消息顺序

[dataset_schema.py](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/dataset_schema.py) 中，`SingleTurnSample` 保存一次问答；`MultiTurnSample` 保存 `HumanMessage`、`AIMessage` 和 `ToolMessage` 列表，并校验工具消息之前的调用关系。

[messages.py](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/messages.py) 的工具请求使用 `name/args`。独立关联 ID 放在消息 metadata，原始事件仍然保留；后续指标未必读取这个 metadata。

框架对象能成功构造，只表示结构符合要求。指标还可能要求 reference、检索证据或预期工具，参见[Ragas 样本概念](https://docs.ragas.io/en/stable/concepts/components/eval_sample/)。

## 转换时别提前丢信息

`native_samples` 保留所有请求及状态，包括无效和被拒绝的请求。不同评分器再按目的投影。评工具选择时看请求，评执行可靠性时看实际运行，评任务完成时看最终状态。

开发、校准和留出划分用于不同阶段；同一任务的近似变体应按题族隔离。数据集课会继续展开这件事。
