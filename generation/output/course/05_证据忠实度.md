# e05: Faithfulness — 每条声明都能找到依据吗

[课程](https://github.com/lovits/learn-agent-evaluation/blob/main/README.md) · [上一课](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e04_retrieval/README.zh.md) · [下一课](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e06_answer_quality/README.zh.md) · [源码导读](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e05_faithfulness/source_walkthrough.md)

> 忠实度检查回答能否从给定证据推出。

## 文档没有写重试次数

上传规范写了认证头、大小上限和413状态码。回答却补了一句：

> 上传失败后会自动重试三次。

这句话听起来合理，但“三次”从哪里来？

Faithfulness 关心回答与本次证据的关系。即使这句话碰巧符合真实系统，给定材料也没有支持它。相反，回答照抄一份过期文档，可以很忠实，却不符合当前系统。

本课不增加 Agent 工具，只在已有回答与检索快照之间接入评分。

## 先拆成能单独判断的声明

把一段回答拆开：

```text
认证头是 X-Project-Token。
最大文件为 2097152 字节。
失败后自动重试三次。
```

旧证据写的上限是1048576字节，因此三句话分别是：有支持、与证据矛盾、证据未说明。

自然语言推断，也就是 NLI，可以帮助理解这几种关系。未提及不等于明确否定；拆句也影响分数，一句复合话拆成几项，分母就会变化。

## DeepEval 先整理证据，再判断回答

[`eval.py`](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e05_faithfulness/eval.py) 构造原生样本：

```python
sample = LLMTestCase(
    input=case["question"],
    actual_output=case["response"],
    retrieval_context=[d["text"] for d in case["documents"]],
)
```

`FaithfulnessMetric` 内部走这条路径：

```text
检索上下文 → truths
回答       → claims
truths + claims → yes / borderline / no → 分数
```

`truths` 是模型从证据整理出的内容，也可能遗漏信息。遇到奇怪分数，要同时检查拆出的 claims 和整理后的 truths。

固定版本默认让 `yes` 与 `borderline` 通过；开启 `penalize_ambiguous_claims` 后只接受 `yes`。

假设裁决为 `[yes, borderline, no]`，默认分数是2/3，惩罚含糊项后为1/3。这是同一组裁决的两种聚合方式。

## Ragas 先生成声明，再做二元支持判断

Ragas collections 的调用是：

```python
metric = Faithfulness(llm=judge)
value = asyncio.run(metric.ascore(
    user_input=case["question"],
    response=case["response"],
    retrieved_contexts=[d["text"] for d in case["documents"]],
)).value
```

内部先生成原子 statements，再让 NLI 判断每项能否由上下文支持，最后计算：

```text
支持的声明数 / 全部判定声明数
```

若三条判定是 `[1, 0, 0]`，结果就是1/3。它没有沿用 DeepEval 默认把 borderline 计入通过的规则。

两个框架还可能拆出不同数量的声明。比较分数前，先确认它们各自数了什么。

## 没有声明时怎么办

“谢谢”可能没有需要核实的事实。固定版本的 DeepEval 对空裁决默认返回1；Ragas 对无声明或无裁决可返回 NaN，空字符串又可能更早触发输入错误。

这些值反映聚合约定。回答有没有完成用户要求，要用其他指标判断。评分代码把未定义结果保存为 `null`，并与请求失败、有效0分分开。

## 证据也属于样本

回答必须与当次检索结果一起保存，不能在评价旧回答时悄悄换成今天的知识库。

[`evidence_key`](https://github.com/lovits/learn-agent-evaluation/blob/main/lessons/e05_faithfulness/code.py) 用文档 ID、哈希和顺序标识证据。内容变化后，旧标注不能直接复用：

```python
def require_same_evidence(old_key, documents):
    if old_key != evidence_key(documents):
        raise ValueError(
            "Evidence changed; old annotations must not be reused"
        )
```

同一句“上限2097152字节”，在旧资料下是矛盾，在新资料下可能有支持。回答没有变化，评价条件已经变了。

## 输入先绑定当次证据

`eval.py` 从已有运行中的 `search_knowledge` 事件取得命中文档，连同回答一起组成样本。教学构造回答和实际产物使用明确来源标记；人工 annotation 不传给裁判。

`evidence_key` 按文档 ID 与 SHA-256 列表生成身份，列表顺序也参与计算。它用于版本比较，不独立提供防篡改证明。

## DeepEval 的主链

[Faithfulness 文档](https://deepeval.com/docs/metrics-faithfulness) · [faithfulness.py](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/metrics/faithfulness/faithfulness.py)

```text
prepare_measure
  → _generate_truths(retrieval_context)
  → _generate_claims(actual_output)
  → _generate_verdicts(claims, truths)
  → _calculate_score
```

输入要求 `INPUT/ACTUAL_OUTPUT/RETRIEVAL_CONTEXT`，不需要 `expected_output`。模型分别整理证据和抽取回答，再生成带理由的 yes/no/borderline。

同步入口依次处理前两个抽取；`a_measure` 可以并发抽取 truths 与 claims，随后再等待裁决。两个抽取都完成以前，无法进行最后判断。

[score_qag_verdicts](https://github.com/confident-ai/deepeval/blob/34db63dd005ebc9a905c8ef4741ae0687c93c14c/deepeval/metrics/utils/qag.py) 决定有效裁决与通过集合。默认接受 yes 和 borderline，含糊项惩罚只接受 yes；空列表默认1。无效标签可能被归一化或丢弃，因此要核对有效裁决数。

`strict_mode` 还会按阈值压低不通过的分数，它与含糊项惩罚是不同配置。`include_reason=False` 只省去整体总结，逐项理由仍可读取。

## Ragas 的主链

[Faithfulness 文档](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/) · [metric.py](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/metrics/collections/faithfulness/metric.py) · [prompt/schema](https://github.com/vibrantlabsai/ragas/blob/8c63f10d500c44efbf24fdb9e2920de2104c321c/src/ragas/metrics/collections/faithfulness/util.py)

```text
ascore
  → _create_statements：问题与回答 → statements
  → _create_verdicts：上下文与 statements → NLI 结果
  → _compute_score：支持比例
  → MetricResult
```

入口检查非空问题、回答和上下文；无 statements 或无 verdict 时返回 NaN。每项 NLI 输出包含 statement、reason 和0/1判定。

本课 `CapturingJudge` 在现代适配器上记录 schema 原始结果，不改变原生提示与算法。`deep_aggregate/ragas_aggregate` 只是帮助手算固定裁决的函数，不承担自然语言判断。

## 低分时先检查哪一步

先看原始证据是否确实包含所需事实，再看 truths/statements 有没有遗漏或合并，最后检查支持关系及聚合政策。

同名指标的差异可能来自抽取、判定和空集约定。Faithfulness 也无法单独识别参考过期、答非所问或漏答，这些留给答案质量指标。
