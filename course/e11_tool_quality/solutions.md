# e11 参考解释

[练习](exercises.md) · [教材](README.zh.md)

1. 写入调用包含 `path` 和 `content` 两个键，`path` 写错成 `other.txt` 但 `content` 相同，非精确参数匹配按并集计权给这次写入打了 `1/2` 分，加上第一步读取正确，综合为 `0.5`。这个分数衡量的是参数字典重合度，不代表文件成功写入了一半，交付结果必须核对目标路径与磁盘文件。
2. 有序子序列（Weighted LCS）只要求匹配到的调用保持先后次序，允许跳过多余步骤；精确匹配则要求调用总数、每个位置的工具名和指定字段完全一致。要检查重复或多余调用，需要看精确匹配或未去重的事件序列。
3. 可以从事件里的 `result["status"]` 和 `output` 看到失败，因为目标路径已存在同名目录，文本写入必然报错。即便工具输出与参考一致，也只说明执行过程符合预设路径，最终任务是否完成还要结合用户目标、保护条件以及允许的替代方案来判断。
4. 如果评测目标就是验证固定文件工具流程，给 `bash` 路线打 `0` 分符合规则；如果评测目标是“只要在工作区内正确完成复制即可”，就应该放宽参考路线或改用基于产物的成功条件，而不该为了迁就参考脚本而禁止原本允许的解法。
5. 不能。只看 `status.txt` 只能确认最终写入了状态文本，必须结合工具事件轨迹确认 Agent 在收到 `denied` 后没有调用 `bash` 越界读取，同时也要把符合策略的 `denied` 视为正常拦截，而非工具故障。
6. 非精确模式的分母是参考调用数，多余的同工具调用不会扣分，且内部按 `ToolCall` 值集合去重。要约束重复调用与多余开销，可以启用 `should_exact_match=True`，或直接基于带唯一编号的原始事件序列核对调用次数。
7. 空调用时没有参数可供判断，返回 `1` 只是 SDK 的默认空值约定，并不代表必要步骤已完成。本课包装层会将其标为 `not_applicable`，靠参考覆盖和产物检查拦住漏调工具的情况。
