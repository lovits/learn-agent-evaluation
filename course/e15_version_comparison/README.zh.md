# e15: 改了参数，真的更好吗？

[e14](../e14_judge_calibration/README.zh.md) → `e15` → [e16](../e16_regression/README.zh.md)

> 固定同一道题，比较两个版本各自交出了什么。

## 问题

只给模型一条资料，可能漏掉认证要求。改成三条，回答或许更完整，也可能混入旧规范。

平均分变高，能直接接受这个改动吗？先看比较时有没有换题、换裁判，以及哪些任务退步了。

## 解决方案

复用第5课的 Agent 和 TinyRAG，候选仍检索3条，只改变送入模型的 context_limit：baseline 为1，candidate 为3。同题各跑两次，第二次交换先后顺序。

![固定同题，只改变上下文条数，保留每次运行和裁决](https://lovits.github.io/learn-agent-evaluation/diagrams/e15-paired-run-flow.svg?v=91ed3bbe050e)

按任务ID和重复编号找到两个版本，再计算差值。分题型看失败，按题族观察波动；延迟和调用量单列。

![有效同题配对后看差值、覆盖率、题族波动和成本](https://lovits.github.io/learn-agent-evaluation/diagrams/e15-comparison-flow.svg?v=e175ff093ef8)

## 工作原理

### 一次只改一个因素

[run_version](code.py) 仍调用已有的 run_task：

```python
run = run_task(case, workspace, k=3,
               context_limit=1 if version == "baseline" else 3,
               root=root, model=next_response)
```

片段省略了工作区创建与记录。查询、任务、知识库、评分量表都相同，改变的只有送入上下文的条数。知识库清单与样本来源均记录哈希；参考依赖的任一文档改变，就先停止比较、复核样本。

本课为控制检索变量，第一步 search_knowledge 由实验固定，工具实际执行 TinyRAG 检索。加 `--live --judge` 后，检索之后才由真实模型继续决定动作和回答。记录中的 decision_origins 区分这两步，不能把它称为从第一步完全自主运行的 Agent。

任务要求只检索一次后回答。若模型继续调用工具，轨迹照常保存，协议条件判失败；不会悄悄删掉额外动作。

### 两个结果必须来自同一道题

[compare](eval.py) 用三项建立索引：

```python
key = (row["case_id"], row["repeat"], row["version"])
```

同一任务、同一次重复，才计算：

```text
差值 = candidate 的质量分 − baseline 的质量分
```

异步完成顺序可能不同，不能把两份结果按列表位置 zip。缺一侧或评分失败，就没有有效差值，保留在 missing_pairs 中；同时报告有效配对数与配对覆盖率。

默认运行中的回答和分数是构造示例，只用于看懂这个计算。真实回答必须用真实裁判评分，不能把 fixture_score 套到新回答上。

### 评分条件保持相同

[quality_metric](eval.py) 使用 DeepEval G-Eval，问题、实际回答、当前参考和实际上下文进入同一个量表：

| 原始分 | 判据 |
|---|---|
| 0 | 矛盾、无依据的断言、空回答或离题 |
| 1 | 有依据但只覆盖部分要求，或明确说明缺少证据 |
| 2 | 所有要求都回答正确，且有上下文支持 |

DeepEval 将它归一化为0、0.5、1，阈值为1。这里评价任务事实覆盖，所以谨慎指出缺资料仍可能只有部分分；第9课更重视合理拒答的量表有不同用途，分数不能直接混比。

先保留语义分，再检查运行完成和单次检索条件。已观察到违反协议时，本课有效质量记0；评分接口异常时记 None，另报覆盖率。

### 重复运行，不能凭空增加题目数

同一道题跑两次，能看执行是否波动。它们仍共享任务、资料和参考，不能当成两道独立新题。

先平均同题差值，再平均题族内任务。本课三个题族等权：跨文档发布与认证、上传规范、当前运费版本。题型分层用于发现“跨文档变好，版本辨别变差”这类平均数掩盖的问题。

[compare](eval.py) 还做一个小型题族 bootstrap：

```python
draws = sorted(mean(rng.choices(values, k=len(values)))
               for _ in range(2000))
```

values 是各题族平均差值。每次带放回地抽题族，再计算均值，观察这些均值的中间约95%范围。这个教学实现用排序位置取近似 percentile 区间，并非 SciPy 默认 BCa。

区间跨过0，说明这批材料不足以排除没有改善的情形。只有三个题族，即使区间很窄，也不足以证明能推广到别的任务。更多重复不会补足题族多样性；缺失配对还可能造成选择偏差。

### 质量之外，再看花了什么

runtime 记录 Agent 阶段总耗时、实际模型请求数和接口报告的 token。固定的首步检索不算模型调用，裁判耗时与用量另记。

输入 token 中的缓存部分不能再加一遍。没有 usage 时保留空值；没有可靠价格表时，美元费用也保留空值。成本可按已确认的输入、缓存、输出单价分别计算，不能凭总 token 猜价格。

当前桥接只记录相同的默认模型选择方式，未确认固定模型快照；顺序交错也不能消除服务端缓存、负载或模型漂移。因此本课结果是限定条件下的观察，接受改动还要核对完整配对、关键退化与运行条件。

## 本课变化

只增加版本循环、同题差值、题族重采样和成本记录。Agent 工具与检索实现保持复用，不增加调度平台。

## 试一下

```sh
python -m course.e15_version_comparison.code
```

1. 按 case_id 和 repeat 手算差值，再找出平均数掩盖的退化。
2. 将一侧评分改成空值，观察配对覆盖率怎样变化。
3. 加 `--live --judge`，区分固定检索步骤和真实模型续跑。
4. 即使整体均分提高，也检查退化题型与费用是否有充分依据。
