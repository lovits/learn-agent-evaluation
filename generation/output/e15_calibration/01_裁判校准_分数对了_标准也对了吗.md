# Chapter 1: 裁判校准：分数对了，标准也对了吗

## 问题

第14课里，Agent 生成的产物通过了检查，效率裁判却给了低分。此时不应立刻修改 Agent，因为另一种可能是：裁判没有正确理解证据，或者评分标准本身含糊。

例如，独立检查记录是“预期值为 9，检查未通过”，Agent 报告也写“值为 9，检查未通过”。这是一份准确报告，应该判为 `pass`；但它没有修好业务问题，不能通过任务完成门禁。报告准确与修复完成是两件事。

本课保持被测 Agent、工具和只读知识库不变，只评测裁判。讲师构造了16条标量记录，而不是运行16次 Agent。所有记录的 `human_reviewed` 都是 `false`：这些标签来自明确合同，不是人工金标准，也不能拿来计算“人类一致率”。

## 解决方案

先把样本按家族隔离成训练集、开发集和留出集，数量分别为4、4、8。同一任务的正确版、错误版、长篇版和英文版必须留在同一集合，避免裁判在开发阶段看过几乎相同的事实。

两版 G-Eval 标准只在开发集比较。v1只要求报告“有用、可信”，故意留下歧义；v2明确要求核对预期值和独立验证状态，接受诚实报告失败，并忽略篇幅、语言与作者身份。候选必须完成全部开发样本评分，选择时先减少误放行，再比较一致率；同分按预定规则选择v2。

选定版本先写入报告，之后才打开留出集。即使留出结果不理想，也要保留，不能回头修改标准。作者知道样本如何构造，因此这里不宣称双盲。

实际流程很短：

```text
构造合同记录 → 家族隔离 → 开发集比较标准
             → 持久化选择 → 留出集验证 → 偏差诊断
```

## 工作原理

**第1步：构造并校验合同记录**

[`make_cases` 与 `validate_cases`](code.py)创建记录，并检查同一家族是否跨集合。下面是[完整代码](code.py)中的节选，其他校验已省略：

```python
# 节选：code.py，省略重复ID等检查
previous = splits.setdefault(row["family"], row["split"])
if previous != row["split"]:
    raise ValueError("Family leakage across splits")
expected = reported["value"] == evidence["expected_value"]
if row["label"] != ("pass" if expected else "fail"):
    raise ValueError("Label contradicts contract")
```

输入是一组带 `family`、`split`、证据和标签的记录，输出是校验后的记录；接入点在评测入口读取 `cases.jsonl` 后。若家族泄漏，开发集可能提前见到留出事实；若标签违反合同，后续一致率再高也没有意义。完整实现还同时核对验证状态，并始终保留未审核标记。

**第2步：用真实 G-Eval 配置评分**

[`score`](eval.py)把必要证据放进 `INPUT`，把报告放进 `ACTUAL_OUTPUT`。以下为节选，异常保留逻辑已省略：

```python
# 节选：eval.py，省略结果整理
judge = GEval(
    name="Completion report accuracy",
    evaluation_steps=STEPS[version],
    evaluation_params=[SingleTurnParams.INPUT, SingleTurnParams.ACTUAL_OUTPUT],
    model=DeepJudge(transport),
    async_mode=False,
    threshold=0.7,
)
```

输入是一条报告及v1或v2标准，输出为0到1的连续分数；达到0.7才映射成 `pass`。它接在开发集和选定版本的留出集评分处。步骤写得含糊，裁判就可能把“诚实失败”误判为报告失败。

自定义后端不支持原始概率接口时，DeepEval 会回退到结构化 schema 路径，细节见[源码导读](source_walkthrough.md)。这里不能声称 Codex 适配器做了概率加权。

**第3步：先冻结选择，再评价留出集**

[`select_version`](code.py)只接收开发结果，并拒绝未完整评分的候选：

```python
# 节选：code.py，省略辅助函数
eligible = [
    v for v in STEPS
    if dev[v] and alignment(dev[v])["unscored"] == 0
]
if not eligible:
    raise ValueError("No fully scored development candidate")
return max(eligible, key=rank)
```

输入是两版完整的开发集预测，输出为选定版本。接入点位于留出评分之前；[`eval.py`](eval.py)会先调用 `atomic_save` 保存版本、阈值和开发结果，再读取留出集。顺序颠倒就会把留出集变成调参集，结果不再是独立验证。

本次实测两版开发判断都正确，因此按预定规则选择v2；这支持“标准表达更明确”，不支持“准确率显著提高”。

**第4步：用原生少样本对齐检查判分**

Ragas 的 `DiscreteMetric.align`把训练示例加入提示，不会训练模型权重：

```python
# 节选：eval.py，省略数据集构造
judge = metric()
judge.align(
    ragas_dataset(train, "training"),
    embedding_model=None,
    max_similar_examples=4,
)
result = judge.validate_alignment(llm, heldout)
```

输入是4条训练记录和留出数据，输出是逐条预测、agreement 与 Cohen’s κ。它接在原始标准评分之后，用来比较对齐前后判分。

`embedding_model=None` 走原生“最近四个示例”回退，对齐阶段产生0次模型请求；它不是向量检索，也不是权重训练。固定源码中还存在旧 embedding wrapper 接口不匹配、参考值与预测值分别过滤 `None` 可能错位，以及κ依赖额外 `scikit-learn` 的风险。若忽略这些边界，可能把错配记录算成一致。

**第5步：适配中文提示，但不冒充语义审核**

`ReportPrompt`提供两个非空示例，并用数字0/1作为标签，避免翻译固定枚举：

```python
# 节选：eval.py，省略异常保存
prompt = ReportPrompt(train)
adapted = asyncio.run(
    prompt.adapt("chinese", llm, adapt_instruction=True)
)
schema_same = prompt.output_model.model_json_schema() == (
    adapted.output_model.model_json_schema()
)
```

输入是原提示、两个示例和目标语言，输出是中文提示。接入点随后让原提示与中文提示评价同四条正确、错误样本。数字、布尔值和 schema 应保持不变；若否定词或“失败也可准确报告”的含义漂移，判分仍会改变。

`language` 字段变化不能证明翻译成功。原生实现遇到空示例会提前返回，连指令也不翻译；即使结构和数值未变，也不足以证明语义无漂移。本次只能记录助手核对结果，人工语义复核仍为 `false`。

**第6步：按内容回映偏差测试**

[`alignment` 与 `equivalent_pairs`](code.py)统计误放行、误拒绝、覆盖率和成对翻转。κ分母退化时返回 `None`，不会伪装成完美一致：

```python
# 节选：code.py，省略计数过程
agreement = correct / n if n else None
kappa = None
if n and not math.isclose(chance, 1):
    kappa = (agreement - chance) / (1 - chance)
```

输入是按唯一ID配对的参考标签和预测，输出包括覆盖率、混淆计数、κ及分歧ID。另一组A/B实验会交换答案顺序，再把字母映射回 `correct` 或 `incorrect` 内容；只比较A/B字母会得出错误结论。

测试覆盖长篇、中英改写和作者身份线索。来源声明未经证实，精确裁判模型也未知，所以不能证明真实自偏好。交换顺序后选择一致，不代表选择正确；小样本没有翻转，也不能证明裁判普遍无偏。
