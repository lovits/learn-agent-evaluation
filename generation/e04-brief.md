# 第4课写作要求

为已完成前三课的Python学习者编写“知识库检索：精度、召回与排序”教材。按Learn Claude Code每次加入一个机制的方式，只新增search_knowledge、只读KB挂载与本课评分。正文从“接POST /upload要知道什么”出发，分小节解释按需加载、检索轨迹、标注文档ID、precision/recall、排序AP、参考答案声明与原生SDK。使用材料中的真实运行摘要，约3000至4500中文字，给可运行命令、练习和验收。参考版本和官方链接在source_walkthrough.md。

必须讲清：
- 复用第2课五工具和权限，循环是可读快照，不引入记忆/计划/子Agent/向量库。借鉴上游SkillLoader“需要时再给模型内容”的思想，未完整移植skill frontmatter和注册系统。磁盘读取候选与模型只看到top3的区别。
- KB是小型合成项目规范，英文按词、中文按双字，查询交集数排序，同分按路径；每文件一个证据单元，id为路径、sha256为内容版本。KNOWLEDGE_DIR映射到/data/knowledge，只读，换目录不需重建镜像。不要声称这是语义检索或生产RAG。
- 独立verify.py断网、工作目录只读，读取真实文件验收三事实和来源。真实Agent检索任务与good/late/missing/empty受控扰动分开；后者不冒充四次Agent输出。
- ID precision=找到相关ID数/返回去重ID数；ID recall=找到相关ID数/标注相关ID数。AP_retrieved分母是本次返回中相关项数，AP_reference分母是全部标注相关数；二者不要混名。MRR与二元NDCG的折扣、方向、分母，排序手算7/12≈0.5833。所有规则高分为好。ID去重保留首个；空返回已知标注记0，空标注本身不当满分。
- 所有返回都相关仍可漏必要证据：只返回认证，ID precision=1、recall=0.5、AP_retrieved=1。参考声明是认证、1048576和413共三条，LLM recall实际约1/3。ID数与claim数不能混为同一单位。参考漏标可使召回虚高。
- DeepEval ContextualPrecision/Recall/Relevancy和Ragas collections ContextPrecisionWithReference/ContextRecall实际运行；Ragas用InstructorBaseRagasLLM适配，不用第3课legacy模型冒充现代接口。原生提示词/schema/校验/调用/verdict/聚合/同步异步要有源码解释。threshold0.7仅为教学约定，epsilon导致约等于1的误差按实际保留。
- DeepEval Relevancy判断问题相关声明，不要求参考；三篇内容排序变化后实测0.6667和0.7143不同，属于模型分句/裁决波动，不是该公式有排序折扣。不能从这次差异推出排序使Relevancy提高。它与文档precision不同。
- WithoutReference源码对照是用response代替reference，仍依赖回答，没运行该原生模型实验。不可宣称本课跑了它。empty在原生SDK层明确skip，规则0，不伪造SDK0；Ragas Recall拒绝空列表。
- 所有失败诚实保留：初次Agent入口残留第2课故障注入提示，多一个被拒的无关Bash；清理提示后Agent重跑成功。初次SDK裁判本身完成，但保存器把Relevancy的verdicts_list误当verdicts，3项错误保留；修复后完整重跑，最终23次裁判请求0错误。两轮SDK共46，Agent两轮共8，生成器另计。不要隐去失败或把保存错误当模型错判。
- 模型不知道验收groundtruth；但教学镜像同时提供教材例题，不能称严格盲测。独立标准不挂给Agent，只说这个具体挂载事实。模型凭据在宿主机。
- 原始prompt、响应、裁判verdict和Agent工具事件都在完整JSON；规则结果、原生分数和判分器运行错误分开。小数据单次运行不足以证明通用可靠性，不测最终回答Faithfulness（第5课）。

实际命令（先在项目目录，Docker Desktop+Python+宿主机Codex已登录）：
宿主机两个终端分别运行 python3 tools/model_bridge.py 和 python3 tools/judge_bridge.py，保持运行；更新过入口代码要重启对应进程。
```sh
docker compose build
docker compose run --rm -T --entrypoint python course -m lessons.e04_retrieval.code
docker compose --profile verify run --rm -T --entrypoint python verifier -m lessons.e04_retrieval.verify
docker compose run --rm -T --entrypoint python course -m lessons.e04_retrieval.eval
```
默认报告在runs/e04-agent.json、e04-agent-grade.json、e04-evaluation.json，重跑会覆盖，比较前先复制。随教材JSON固定不覆盖。
替换挂载：KNOWLEDGE_DIR=/绝对路径 docker compose run --rm -T --entrypoint python course -c 'from lessons.e04_retrieval.code import search_knowledge; print(search_knowledge("你的查询词"))'。路径必须是实际存在目录，不把占位符当真实命令执行。
教材阅读用docker compose up -d，http://localhost:8765/lesson4。

正文讲解要自然、有耐心，像和读者一起对照一次检索结果。去掉模板化开场、重复小结、装饰性三连和空泛升华。不虚构个人经历，不改命令或数字。只给必要代码片段并标明简写，链接完整code/eval/verify/source_walkthrough/exercises/solutions/run_summary。不要加入Mermaid、未渲染LaTex和多余示意图。
