# 第3课教材任务

围绕第2课编程Agent继续学习，仅新增独立评分，不再实现Agent。用PocketFlow将本课code.py/eval.py、四个受控回答、实际裁判运行摘要、源码导读、练习/答案组织成中文教材，约2500至4000字。

从“程序输出48，用中文说四十八算不算正确”讲起。按Learn Claude Code的小步组织：先精确匹配，再JSON合同、真实状态、集合precision/recall/F1，再rubric与LLM-as-a-Judge，最后GEval、DAGMetric、AspectCritic原生SDK调用。正文选必要片段，链接完整代码。给出指标方向、分母、阈值、空集合、None错误、适用边界。F1手算2/3，集合不保留重复顺序和参数。

必须说明：四条数据是受控回答变体，裁判调用真实，第2课Agent未新增执行；artifact_verified是夹具事实，正式项目必须来自独立验收器。JSON格式分、语义分和状态分不能相互替代，正文字面正确不证明完成。评分标准忽略JSON格式但要求语义48且不得虚报完成。GEval阈值0.7，DAG的True/False叶子10/0归一化，Ragas二元1为通过；不比较三者数值大小的优劣。score=null表示裁判失败，0是成功裁决的不通过。

保留固定源码分析、官方文档链接、提示词与schema/结果/聚合/同步异步说明。自定义模型没有logprobs，不声称概率加权。DAG分数映射固定、模型节点仍随机；Ragas当前legacy API严格按固定源码解释，不把strictness属性等同实际多次独立投票。小样本一次运行不能证明可靠性，需要人工校准和独立留出集。模型具体ID缺失、费用未测就如实保留。

运行：宿主机 python3 tools/judge_bridge.py；另一个终端 docker compose build，然后 docker compose run --rm -T --entrypoint python course -m lessons.e03_judges.eval。只挂载既有KB/runs/workspaces，不导出凭据；裁判只看样本文本与提供的事实，不执行学生代码。报告默认runs/e03-latest.json，用户重跑前可复制保留旧文件。随教材的example_report.json为固定实测。

讲解面向已经会Python的读者：具体、自然、耐心，避免“深入探讨”“至关重要”、装饰性排比、每节机械小结或虚构亲身经历。以真实例子解释，事实和命令不能润色变形。提供六道练习和参考答案链接，衔接第4课检索评测。请使用run_summary.md的实际数字，不编造结果。
