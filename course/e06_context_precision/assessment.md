课程编写助手对照参考，把提供命令和发布条件的 release 标为 1，将不提供这些内容的 logs、auth 标为 0。这是构造的教学标签，不是独立人工金标准。

有用项前移、后移和天气噪声均为控制条件，不声称是检索器真实返回的新结果。固定标签计算与真实模型裁决分别保存。

## DeepEval 原生评分

运行编号 `c675aad87cd140e6af3aaa0112643740`，在 Docker 中执行 `--judge`，实际发送五次模型请求：原序与前移序各一次片段级判定，以及原序三个片段各一次陈述级判定。`include_reason=False` 省去额外的总分解释请求，逐项裁决仍保留理由或陈述。

| 指标与条件 | 实际裁决 | 实际分数 |
|---|---|---:|
| Contextual Precision，原序 | no、yes、no | 0.5 |
| Contextual Precision，前移序 | yes、no、no | 1 |
| Contextual Relevancy，原序 | 共 9 条陈述，其中 4 条 yes | 4/9，约 0.4444 |

两次 Precision 判定与固定教学标签一致，所以这一次可沿相同标签解释顺序影响。不能预先假定每次模型都会保持相同判定；原始返回均保留。

Relevancy 将日志天数等信息判为无关，同时把“日志时间不决定检查命令”“认证头不决定能否发布”判为与问题相关；发布规范贡献两条相关陈述。它没有问这些片段能否给出参考答案，也没有按三份文档等权平均。因此 4/9 不能当作“有用文档占比”，也不能与 0.5 直接比较大小判断哪个框架更好。

本课没有生成新的 Agent 回答，样本 `actual_output` 为空。这个固定版本的两个原生指标只读取问题、候选，以及 Precision 所需的参考。本课没有运行 Ragas 或另一次框架评分。

## 错误与解释边界

裁判返回数量少于字符串候选数时，适配层将 Precision 结果记为对齐错误，分数和是否达标为空；没有收到判定的项不自动算作无关。

软件检查用构造响应验证原生指标允许本课不生成回答的输入路径，并区分两条片段判定与四条陈述判定。另检查固定数量下的重排、尾部噪声、多个相关位置、空列表及非法标签。这些是受控软件检查，不冒充真实模型请求。

只有一个公开教学问题，不能据此推断业务表现。标签判据、模型裁决、分数单位和分母需随结果一起阅读；默认阈值也没有经过业务校准。
